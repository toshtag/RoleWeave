# ADR 0054: 保存に上限を置き、新着は前回以降の分だけ通知する

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P13 の完了条件は「求人を保存し検索条件を保存できる」「新着求人が通知される」を含む。

気になる求人を覚えておく手段がなかった。
探し直すには、同じ条件をもう一度入力することになる。

新着の求人に気付く手段もなかった。求職者は思い出したときに見に来るしかない。

条件は求人の検索（ADR 0021）がすでに持っている。

## 決定

- 保存した求人（`saved_job_postings`）と検索条件（`saved_searches`）を
  プロフィールへ従属させる
- 同じ求人を 2 回保存できない。一意索引でも拒否する
- 条件は**検索が使う項目に限る**（`Public::JobPostingsController::SEARCH_KEYS`）
- **保存できる件数に上限を置く**（求人 200 件、条件 20 件）
- 新着の通知は rake タスクから行う。**自動実行はしない**
- **前回の通知より後に公開された求人だけ**を対象にする
- 一致がなくても、通知の時刻は進める
- 通知を受け取るかどうかは、**条件ごと**に決める
- メールの本文に求人の中身を書かない。件数だけを伝える

## 理由

条件を検索が使う項目に限るのは、別の項目を許すと
検索の側と食い違う条件が保存されるためである。
保存した条件を再実行しても同じ結果にならない状態を作らない。

上限を置くのは、通知の処理が保存の件数に比例するためである。
無制限にすると、1 人が数千件の条件を保存でき、通知の実行が終わらなくなる。
上限は「使い方として妥当な範囲」で置いた。**値そのものに強い根拠はない。**

自動実行しないのは、いつ通知するかが運用の判断であるためである
（保持期限（ADR 0046）と同じ理由）。
毎日か毎週かは、運用する人が決める。

前回以降に限るのは、**同じ求人を 2 回通知しないため**である。
同じ通知が繰り返されると、通知そのものが読まれなくなる。

一致がなくても時刻を進めるのは、次回に古い求人が混ざらないようにするためである。
進めないと、条件に一致する求人が現れた時点で、
それ以前のすべての求人が「新着」として通知される。

通知の可否を条件ごとにするのは、条件によって関心の強さが違うためである。
「保存はしておきたいが、通知は要らない」を選べるようにする。

メールに求人の中身を書かないのは、通知（ADR 0042）と同じ理由である。
何を探しているかが受信箱に残り続ける。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 条件を自由な JSON にする | 検索の側と食い違う条件が保存される |
| 保存の件数を無制限にする | 通知の実行が終わらなくなる |
| 新着を自動で通知する | いつ通知するかは運用の判断である |
| 通知の時刻を持たない | 同じ求人が何度も通知される |
| 一致がないときは時刻を進めない | 一致した時点で、それ以前のすべてが新着になる |
| 通知の可否を利用者単位にする | 条件によって関心の強さが違う |
| メールへ求人の題名を書く | 何を探しているかが受信箱に残り続ける |

## 影響

- 通知は rake タスクを呼ばない限り届かない。運用で回す前提である
- 保存した求人が公開でなくなることがある。一覧では状態を添えて出す
- 保存はプロフィールの削除で消える。保持期限の対象にはしない（ADR 0046 へ記載）
- 通知の頻度（毎日・毎週）の設定はない。呼ぶ間隔が頻度になる
- 保存した条件の共有はできない
