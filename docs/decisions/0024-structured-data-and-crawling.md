# ADR 0024: 構造化データ・sitemap・robots.txt を動的に配信する

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P5 の完了条件は「sitemap と robots が配信される」を含む。
P5 の対象範囲は「構造化データ」と「robots 制御」を含む。

Rails 生成時の `public/robots.txt` は `User-agent: *` と案内のコメントしか持たない。
sitemap の場所を示しておらず、ログインが要る画面も除外していない。

sitemap と robots.txt は、動くホスト名に依存する。
自己ホスト可能な OSS として配布するため、ホスト名を静的ファイルへ書けない。

構造化データがないと、求人が「求人」として認識されない。
題名と本文の区別、勤務地、雇用形態、給与は、HTML の見た目からは判定されない。

## 決定

- 求人の詳細へ JSON-LD の `JobPosting` を出力する
- 出すのは入力された項目だけとし、未入力の項目は書かない
- 一覧には構造化データを出さない
- `sitemap.xml` を動的に生成する。
  ロケールごとの入口・求人一覧と、公開中の求人を並べる
- `robots.txt` を動的に生成し、sitemap の場所と除外する経路を書く
- Rails 生成時の `public/robots.txt` は削除する
- どちらもロケールを持たない URL（`/sitemap.xml`、`/robots.txt`）で配信する
- route は `format: false` とし、拡張子を含む path をそのまま扱う

## 理由

動的に生成するのは、ホスト名を静的ファイルへ書けないためである。
`Sitemap:` の行は絶対 URL を要求する。
利用者ごとに書き換えを求めると、書き換え忘れが「sitemap が見つからない」形で現れる。

静的な `public/robots.txt` を削除するのは、
Rails が `public/` を先に返すためである。残すと動的な経路へ到達しない。

未入力の項目を書かないのは、空で書くと
「値がない」ではなく「空という値がある」と解釈されうるためである。
給与が `0` と読まれるのは、未記載より悪い。

一覧に構造化データを出さないのは、一覧が求人そのものではないためである。
`ItemList` を出す選択肢もあるが、詳細がすでに個別に認識される以上、
一覧の分は重複した情報になる。

`format: false` にするのは、既定の解釈では `.xml` が format として切り出され、
URL helper が拡張子を失うためである（`/sitemap` になる）。
`Sitemap:` の行と実際の URL が食い違う。

除外する経路を並べるのは、意味のない巡回と検索結果への露出を避けるためである。
**除外は「見えてはいけない」ための仕組みではない。**
到達できる URL は robots.txt に関わらず到達できる。
公開してはいけないものは、経路の側で拒否する（ADR 0013、ADR 0020）。

## 除外する経路

ロケールごとに次を除外する。

- `/account`、`/organizations`、`/operator` — ログインが要る
- `/session`、`/registration`、`/password_reset` — 検索結果から入る意味がない
- `/confirmation`、`/invitation` — token を持つ。巡回で消費されうる

`/jobs` は除外しない。ここが検索から入ってほしい経路である。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 静的な `robots.txt` を書く | `Sitemap:` に絶対 URL が要り、ホスト名を書けない |
| 静的な `sitemap.xml` を置く | 求人の増減に追随できない |
| 未入力の項目も空で書く | 「空という値がある」と解釈されうる |
| 一覧へ `ItemList` を出す | 詳細がすでに個別に認識され、重複した情報になる |
| route の `format: false` を使わない | URL helper が拡張子を失い、`Sitemap:` と実際の URL が食い違う |
| robots.txt で非公開を守る | 到達できる URL は robots.txt に関わらず到達できる |

## 影響

- 求人が増えると sitemap が長くなる。分割の閾値（5 万 URL / 50MB）に達した場合は、
  索引 sitemap への分割が要る。現時点では扱わない
- sitemap は毎回データベースから組み立てる。キャッシュは P5-T6 で扱う
- `hreflang` を出していない。同じ求人が日英で別 URL になるため、
  相互参照を示す余地がある。必要になった時点で判断する
- 組織の構造化データ、パンくずの構造化データはない
- 検索エンジンへの登録通知（ping）は行わない
