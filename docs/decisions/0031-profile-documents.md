# ADR 0031: 添付は PDF だけに絞り、自前の経路から配る

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P6 の完了条件は「ファイルを添付できる」を含む。

Active Storage は設定だけが入っており、テーブルがなかった。

添付されるのは履歴書と職務経歴書である。
これらの PDF は、このアプリケーションが持たないと決めた情報
（生年月日・性別・顔写真、ADR 0026）を含みうる。
持たないと決めた情報が、ファイルの形で入ってくる。

Active Storage の既定の配信経路は署名付き URL である。
署名は推測できないが、URL を知っていれば誰でも開ける。

## 決定

- Active Storage のテーブルを追加し、保存先は `Disk` とする
- プロフィールへ履歴書（`resume`）と職務経歴書（`curriculum_vitae`）を 1 つずつ添付する
- **受け付ける形式は `application/pdf` だけとする**
- 1 つあたりの上限を 10 MB とする
- 配信は自前の経路から行い、Active Storage の署名付き URL へリンクしない
- 常に `Content-Disposition: attachment` で返す
- 企業へ見せるかは `documents_visible` として別に持つ。既定値は偽
- **公開範囲と添付の設定の両方が開いているときだけ、企業から取れる**
- 種類（`kind`）は決まった 2 つだけを受け取り、それ以外は 404 とする
- 外部のオブジェクトストレージ用の依存は足さない

## 理由

PDF だけに絞るのは、Office 文書がマクロを持てるためである。
受け取った側が開く前提のファイルであり、開く側の危険をアプリケーションが作ることになる。
PDF も安全ではないが、マクロを埋め込んだ文書ほど直接ではない。
形式を増やすかは、受け取る側の運用（どこで開くか）が決まってから判断する。

自前の経路から配るのは、署名付き URL が「知っていれば開ける」ためである。
個人の履歴書をその形で配ると、URL が渡った先すべてから読める。
ログイン状態も公開範囲も確かめられない。
自前の経路であれば、毎回両方を確かめられる。

`Content-Disposition: attachment` で返すのは、ブラウザーの中で開かせないためである。
返す規則は 1 か所（`DocumentDownload`）に置いた。
本人用と企業用で別々に書くと、片方だけ変わったときに危険がそこから戻る。

添付の公開を別に持つのは、履歴書が
「このアプリケーションが持たないと決めた情報」を含みうるためである。
プロフィールを見せるという判断が、そのまま生年月日や顔写真を渡す判断になってはならない。
設定画面にも、その旨を書いた。

両方の設定を要求するのは、片方の設定だけで渡ることを避けるためである。
公開範囲を開いたときに添付まで一緒に開くと、
利用者は「プロフィールを見せた」つもりで履歴書を渡すことになる。

種類を決まった 2 つに限るのは、受け取った文字列をそのまま
`public_send` へ渡すと、ほかのメソッドを呼べてしまうためである。

`Disk` に留めるのは、外部のオブジェクトストレージが依存の追加を要するためである。
自己ホストを前提とするため、追加の外部サービスなしで動く状態を既定とする。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| Office 文書も受け付ける | マクロを持てる。開く側の危険をアプリケーションが作る |
| 形式を検証しない | 実行可能なファイルがそのまま配られる |
| Active Storage の署名付き URL で配る | URL を知っていれば誰でも開ける。公開範囲を確かめられない |
| `Content-Disposition: inline` で返す | ブラウザーの中で開き、内容に応じた挙動が起こりうる |
| 添付の公開を公開範囲へまとめる | プロフィールを見せる判断が、そのまま履歴書を渡す判断になる |
| 種類を受け取ってそのまま `public_send` する | ほかのメソッドを呼べてしまう |
| S3 などを既定にする | 追加の外部サービスなしで動かなくなる |
| ウイルス検査を入れる | 外部の依存とスキャンの運用が要る。必要になった時点で判断する |

## 影響

- `storage/` を永続化しないと、添付だけが失われる。
  データベースには記録が残るため、開けない添付として現れる。
  運用は [`docs/development/file-storage.md`](../development/file-storage.md) に書いた
- バックアップは、データベースと `storage/` を同じ時点の組で取る必要がある
- 添付の版の履歴は持たない。差し替えたら古いファイルは残らない
- 外部のオブジェクトストレージを使う場合は、依存の追加と ADR が要る
- 添付の経路は、前段のキャッシュに載せてはならない。
  同じ URL への応答が閲覧者によって変わる
- 削除・匿名化（P6-T8）では、添付も消えることを保証する
- エクスポート（P6-T7）に添付そのものを含めるかは、そのタスクで決める
