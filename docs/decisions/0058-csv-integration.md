# ADR 0058: CSV は外部の識別子で照合し、取り込んだ求人は下書きにする

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P14 の完了条件は「CSV の入出力ができる」
「同じ入力を再実行しても二重処理されない」「連携の実行結果が履歴として残る」を含む。
対象範囲には「冪等性」「失敗隔離」も含まれる。

求人は 1 件ずつ画面から作るしかなかった。
すでに別の仕組みで求人を持っている組織は、全部を手で入れ直すことになる。

取り込みは失敗する。列が足りない、値が不正、文字コードが違う。

## 決定

- 求人へ**外部の識別子**（`external_key`）を持たせる。組織の中で一意とする
- CSV の行は `external_key` で照合する。**あれば更新、なければ作成**
- `external_key` のない行は取り込まない
- 取り込んだ求人は必ず**下書き**とする
- **1 行の失敗で全体を止めない。**行ごとに数え、失敗の内容を残す
- 失敗の行番号は**ファイルの行**に合わせる（見出しの分だけずらす）
- 実行の結果（`integration_runs`）を残す
- 扱えるのは組織の**管理者だけ**とする
- **応募者・候補者の CSV は作らない**
- `csv` を Gemfile へ足す（Ruby 3.4 以降は bundled gem）

## 理由

外部の識別子で照合するのは、**同じ入力を再実行できるようにする**ためである。
取り込みは途中で失敗する。失敗したときに、もう一度実行できなければ直せない。
内部の id で照合すると、外部の仕組みはこちらの id を知らないため使えない。

`external_key` のない行を取り込まないのは、照合できない行を作ると
次の実行で必ず重複するためである。

取り込んだ求人を下書きにするのは、**CSV が公開の判断を迂回する経路になってはならない**ためである。
審査（ADR 0017）で申請と承認を分けた意味が、取り込みで消える。

1 行の失敗で止めないのは、100 行のうち 1 行の誤りで残り 99 行が入らないと、
実務では使えないためである。
そのぶん、**何行目がなぜ失敗したかを残す**必要がある。

行番号をファイルの行に合わせるのは、直す人が表計算ソフトで探すためである。
データ行の通し番号では、見出しの分だけずれて見つけにくい。

応募者・候補者の CSV を作らないのは、**個人情報を持ち出す経路を増やさない**ためである。
本人によるエクスポート（ADR 0032）はあるが、それは本人が自分のものを出す仕組みである。
企業が候補者の一覧を CSV で落とせる経路は、公開範囲（ADR 0030）の設計と食い違う。

`csv` を Gemfile へ足すのは、Ruby 3.4 以降 bundled gem になり、
Bundler の管理下では明示しないと読み込めないためである。
自前で実装する案は採らなかった。
引用符の中の改行やカンマの扱いを誤ると、**取り込んだデータが黙って壊れる**。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 内部の id で照合する | 外部の仕組みはこちらの id を知らない |
| 識別子なしで題名などから照合する | 題名が変わると別の求人として増える |
| 取り込みで公開状態にできる | CSV が公開の判断を迂回する経路になる |
| 1 行でも失敗したら全体を取り消す | 100 行のうち 1 行の誤りで残りが入らない |
| 失敗の内容を残さない | 何を直せばよいか分からない |
| 応募者・候補者の CSV を作る | 個人情報を持ち出す経路が増える |
| CSV の解析を自前で書く | 引用符・改行の扱いを誤り、データが黙って壊れる |

## 影響

- `external_key` は取り込みのためだけの列である。画面からは設定できない
- 取り込みで**削除は行わない**。CSV にない求人は残る
- 文字コードは UTF-8 を前提とする。Shift_JIS のファイルは失敗する
- 実行の履歴は組織の削除で消える。保持期限の対象にはしない
- スケジュール実行はない。画面から実行する
