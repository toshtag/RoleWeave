# ADR 0050: 負荷試験は手元で再現し、容量は前提を明示して外挿する

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P11 の完了条件は次を含む。

- 再現可能なローカルまたは CI 向け負荷試験の実測値が記録されている
- 明示した前提条件に基づく 50 万 MAU の容量モデルが文書化されている
- 200 万 MAU は構造変更や追加投資を判断するための基準であり、
  初期環境の保証値ではないことが明記されている

非目標に「50 万 MAU 相当の実トラフィックを発生させること」
「本番規模のインフラを事前構築すること」がある。

性能について、これまで測った数字が 1 つもなかった。
「`ILIKE` が遅い」も「既読の行が増える」も、すべて推測だった。

## 決定

- 負荷試験を rake タスク（`seed` / `measure` / `clean`）として用意する
- 測定は**アプリケーションの中**（`ActionDispatch::Integration::Session`）で行う。
  外部の負荷ツールを足さない
- 応答の状態も返す。200 以外を測っても意味のある数字にならない
- データ量を変えて 2 点以上を測り、**増え方**を見る
- 実測値と見積もりを**別の文書**に書く
  - `docs/performance/load-test-results.md`（測った値だけ）
  - `docs/performance/capacity-model.md`（前提を明示した見積もり）
- 実測値には、測った環境とデータ量を必ず書く
- **200 万 MAU は保証値ではなく、構造を変える判断の基準**として書く
- 遅い経路には「いつ直すか」の基準を書き、**いまは直さない**
- OpenTelemetry は導入せず、境界だけを文書化する

## 理由

外部の負荷ツールを使わないのは、自己ホストの利用者が
このリポジトリだけで同じ手順を踏めるようにするためである。
`k6` や `wrk` を前提にすると、測るために別の道具を用意することになる。

その代わり、測っているのはアプリケーションの中の時間だけである。
Puma のキュー待ち・TLS・ネットワークは含まれない。
**含まれないことを実測の文書へ明記する。**書かないと、実際の体感時間と誤解される。

実測と見積もりを分けるのは、混ぜると区別がつかなくなるためである。
「50 万 MAU で 77 req/s」は計算であり、測った値ではない。
同じ文書に並べると、どちらも同じ確からしさに見える。

前提を表として書くのは、前提が変われば結論も変わるためである。
「1 利用者あたり月 40 要求」は置いた値であり、根拠のある値ではない。
そう書いておかないと、根拠のある値として引用される。

200 万 MAU を保証値としないのは、確かめていないためである。
確かめていないものを「対応できる」と書くことはできない。
代わりに、**何を見たら構造を変えるか**の基準を書く。

遅い経路をいま直さないのは、先回りの作り込みが
測っていない前提に基づく複雑さを増やすためである。
基準（求人 1 万件、p95 1 秒）に達したときに、測った値とともに判断する。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 外部の負荷ツール（k6・wrk）を前提にする | 測るために別の道具が要る。自己ホストの前提と合わない |
| 実測と見積もりを 1 つの文書へ書く | どちらも同じ確からしさに見える |
| 前提を書かずに結論だけを書く | 前提が変わったときに、結論の妥当性を確かめられない |
| 200 万 MAU を「対応可能」と書く | 確かめていない。書けば保証と読まれる |
| 遅い経路を先に直す | 測っていない前提に基づく複雑さが増える |
| OpenTelemetry を先に入れる | 送り先がない。測る場所はすでに決まっている |
| 実トラフィックを発生させる | 非目標である |

## 影響

- 測定値は development のものである。production では eager load とキャッシュの働きが違う。
  **絶対値ではなく増え方を見るための測定**である
- sitemap.xml とキーワード検索が、件数とともに遅くなることが数字で分かった。
  対応の基準は実測の文書に書いた
- 負荷試験のデータは専用の印（組織名・メールアドレス）を付ける。
  `clean` で消せるが、本番のデータベースでは実行しない
- 容量モデルの前提は、運用が始まったら構造化ログ（ADR 0048）から数え直す
