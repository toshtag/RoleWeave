# ADR 0063: 受け取る入力の大きさは、読む前に止める

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

リクエストの本文の大きさに上限がなかった。
Puma にも Rack にも既定の上限はなく、`config/puma.rb` でも設定していない。

そのうえで、大きさを前提にした処理が 2 か所にあった。

**1. 求人の CSV の取り込み**

`Organizations::JobPostingImportsController#create` は
`file.read` でアップロードの全体をメモリへ読み、
`CSV.parse` が全行を一度に配列へ展開していた。
バイト数の上限も行数の上限もない。

同じ経路に、型を確かめていない箇所があった。
`params[:file]` が文字列でも `read` を呼ぶため、
`file=abc` を送ると `NoMethodError` になり 500 を返した。

**2. 履歴書・職務経歴書の添付**

`CandidateProfile` は 10 MB の上限を検証している（ADR 0031）。
しかしこれはモデルの検証であり、そこへ届く前に
**Rack がリクエストの本文の全体を一時ファイルへ書く**。
検証が拒否するのは、書き終えた後である。

どちらも認証を要する。
しかし脅威モデルの「登録した利用者」は攻撃者に含まれ、
守る対象には「サービスの継続」が入っている。

## 決定

- リクエストの本文の上限を持つ middleware（`RequestBodyLimit`）を自前で置く。
  新しい依存を足さない
- 上限は 20 MB とする。添付の上限（10 MB）へ multipart の枠の分を足した値である
- middleware は stack の**先頭**（`insert_before 0`）へ置く
- 超えた場合は 413 を返す。応答は `public/413.html` / `413.en.html` の静的な HTML とする
- 取り込みの上限を `JobPostingCsv` の定数として置く（5 MB、10,000 行）
- 上限を超えた取り込みは**1 件も取り込まない**
- CSV は 1 行ずつ読む（`CSV.parse` ではなく `CSV.new(...).each`）
- `params[:file]` が `read` に応答することを確かめる

## 理由

**middleware を先頭へ置く**のは、後ろへ置くと
「上限を超えたことに気付いた時点で、すでに受け取っている」ためである。

**申告された大きさ（`CONTENT_LENGTH`）だけを見る**のは、
本文を読んでから数えると、数え終えた時点で受け取っているためである。
申告のない本文（`Transfer-Encoding: chunked`）はここでは止まらない。
その場合の上限は前段（逆プロキシ、Puma）が持つ
（`docs/development/reverse-proxy.md`、ADR 0062）。
**この判断だけで、あらゆる大きさの入力を止められるわけではない。**

413 に静的な画面を返すのは、ほかのエラー画面と同じ理由による（ADR 0003）。
413 は例外ではないため exceptions_app を通らない。
429 と同じく、middleware が直接返す。

**取り込みの上限を別に持つ**のは、本文の上限（20 MB）が
取り込みにとっては大きすぎるためである。
求人の 1 件は数 KB であり、10,000 件の取り込みは
手作業の移行として十分な規模である。

**1 件も取り込まない**のは、途中まで取り込むと
「同じ入力を再実行してよい」と言えなくなるためである（ADR 0058）。
行数は取り込む前に数え、上限を超えた時点で数えるのをやめる。

**型を確かめる**のは、入力の誤りを 500 で返さないためである。
500 は「こちらが壊れた」という意味であり、
選んだファイルが違うことは利用者に伝わらない。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| モデルの検証だけで足りるとする | 検証が動くのは、本文を書き終えた後である |
| 上限を Puma の設定だけに任せる | Puma に本文の大きさの設定はない。前段に依存する |
| `rack-attack` などを入れる | 新しい依存が増える。20 行で足りる |
| middleware を stack の後ろへ置く | 気付いた時点ですでに受け取っている |
| 本文を読みながら数える | 数え終えた時点で受け取っている |
| 413 を動的に描画する | 大きな入力が届いている状況で、描画経路に依存することになる |
| 取り込みの上限を本文の上限と同じにする | 求人の CSV にとって大きすぎる。数十万行を受け入れることになる |
| 上限を超えた分だけ切り捨てて取り込む | 半分だけ入った状態が残る。再実行してよいと言えない |
| 行数を取り込みながら数える | 止めた時点で、途中まで入っている |
| ファイルでない値で 500 を返し続ける | 入力の誤りが「こちらが壊れた」として伝わる |

## 影響

- **`Transfer-Encoding: chunked` の本文は、この middleware では止まらない。**
  前段の設定に依存する。脅威モデルへ受け入れているリスクとして残した
- 20 MB を超える正当な入力はない。添付の上限は 10 MB である。
  添付の上限を上げるときは、`RequestBodyLimit::MAX_BYTES` も上げる
- 10,000 行を超える取り込みは、ファイルを分けることになる
- 上限の値は定数である。変えるには再起動が要る
- 413 の静的ページは、ほかのエラー画面と同じスタイルを持つ（ADR 0003）
