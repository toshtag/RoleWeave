# ADR 0006: パスワードを bcrypt で保存し、長さだけを条件にする

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0005 でアカウントの識別子を決めた。次に必要なのは、本人だけが知る秘密である。

パスワードの保存方式は、後から変える費用がとくに高い。
保存済みの値は元へ戻せないため、方式を変えるには
全利用者へ再設定を求めるか、次回ログイン時に移行する仕組みを足すことになる。

パスワードの条件（policy）も、後から厳しくすると既存の利用者が
次のログインで弾かれるか、移行の経路が別に必要になる。

`has_secure_password` は `bcrypt` gem を必要とする。
Rails 生成時の Gemfile にコメントとして含まれているが、有効化は新規依存の追加にあたる。

## 決定

- パスワードは `has_secure_password` と `bcrypt` で保存する
- 列は `users.password_digest` とし、`null` を許可しない
- 平文はデータベース、ログ、例外の出力のいずれにも残さない
- 最小長は 12 文字とする
- 上限は bcrypt が扱う 72 バイトとし、文字数ではなくバイト数で判定する
- 文字種の組み合わせ（大文字、数字、記号の必須化）は要求しない
- パスワードの有効期限、履歴の禁止、定期変更の強制を設けない
- 漏えいパスワード一覧との照合は、この ADR では行わない
- 長さの検証は自前で持つ。`has_secure_password` の既定の検証だけには依存しない

## 理由

`bcrypt` を使うのは、ハッシュ化を自前で実装しないためである。
ソルトの生成、反復回数の値への埋め込み、比較の時間差対策のいずれも、
自作すればそのすべてが検証の対象になる。
`has_secure_password` は Rails 本体の機能であり、
`authenticate_by` によるタイミング差の緩和も同じ経路で使える。

`password_digest` を `null` 不許可にするのは、
認証手段のないアカウントに用途がないためである。
外部認証と SSO は P2 の非目標であり、
「パスワードを持たないアカウント」を先回りして許可する理由がない。

最小長を 12 文字にするのは、長さが推測の困難さへ最も直接効くためである。
NIST SP 800-63B は利用者が選ぶ秘密の下限を 8 文字とするが、
これは下限であって推奨値ではない。
このプロジェクトは応募者の個人情報を扱うため、下限より一段厳しい値を選ぶ。

上限を 72 バイトにするのは、bcrypt がそれを超える入力を切り捨てるためである。
切り捨てを黙って受け入れると、入力の一部が認証に使われない状態になる。
利用者は長いパスワードを設定したつもりでいるが、実際に効いているのは先頭だけになる。

判定をバイト数で行うのは、日本語を含むパスワードで 1 文字が複数バイトになるためである。
文字数で判定すると、25 文字の日本語（75 バイト）が上限内と判断され、
bcrypt の側で切り捨てられる。

文字種の組み合わせを要求しないのは、
その強制が記憶しやすい規則的な変形を誘発するためである。
「大文字と数字と記号を含む」を満たすために、
利用者は同じ単語の末尾へ `1!` を足す。
これは推測の難しさをほとんど変えないまま、記憶と入力の負担だけを増やす。
NIST SP 800-63B も、組み合わせ規則を課さないことを求めている。

有効期限と定期変更を設けないのは、同じ理由による。
定期変更の強制は、規則的な変形（末尾の数字を 1 つ進める）を生む。

長さの検証を自前で持つのは、`has_secure_password` の既定の検証が
72 バイト超だけを見るためである。既定に任せると、短いパスワードをそのまま受け入れる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| `argon2` gem | Rails 本体が前提にしていない。`has_secure_password` から使うには追加の実装が要る |
| `OpenSSL::PKCS5` などで自作する | ソルト管理、反復回数、比較の実装をすべて自前で検証することになる |
| 可逆な暗号で保存する | 鍵の漏えいが全利用者のパスワード漏えいに直結する |
| パスワードを持たず、メールリンクだけで認証する | P2 の完了条件を満たさない |
| 最小長を 8 文字にする | 応募者の個人情報を扱う前提に対して、下限をそのまま採る理由がない |
| 文字種の組み合わせを必須にする | 規則的な変形を誘発し、長さを伸ばすほどには推測を難しくしない |
| 上限を文字数で判定する | 日本語を含むパスワードで、bcrypt が切り捨てる長さを受け入れる |

## 影響

- `bcrypt` gem が依存へ加わる。バージョンは `Gemfile.lock` で固定し、
  更新は依存関係更新のタスクとして扱う（`docs/development/workflow.md`）
- パスワードの検証（`authenticate`、`authenticate_by`）は 1 回あたり数十ミリ秒かかる。
  ログインの経路を作るタスクでは、この費用を前提に試行回数の制限を設計する
- 漏えいパスワード一覧との照合を行っていない。
  他所で漏えいした組み合わせをそのまま設定できる状態が残る。
  照合は外部サービスへの問い合わせか、辞書の同梱を伴うため、
  導入するかどうかは P10 Privacy, Security and Operations で判断する
- パスワードの条件を後から厳しくすると、既存の利用者が次のログインで弾かれる。
  変更する場合は、移行の経路を同じタスクで決める
