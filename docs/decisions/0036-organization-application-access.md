# ADR 0036: 企業が見るのは応募時点の写しとし、公開範囲は応募中だけ開く

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

ADR 0030 で公開範囲に `applied_organizations`（応募した企業だけ）を用意した。
応募の仕組みがなかったため、この時点では誰にも見えない状態にしていた。
判定は `CandidateProfile` の 1 か所にあり、そこを拡張すると記録している。

ADR 0034 で、応募は応募時点の写しを持つと決めた。
ADR 0035 で、取り消した応募も記録として残ると決めた。

企業側から応募を見る経路がまだない。
その経路を作るとき、次の 2 つを決める必要がある。

1. 企業が見るのは、応募時点の写しか、現在のプロフィールか
2. 取り消した応募の相手のプロフィールを、企業が見続けられるか

## 決定

- 応募の一覧・詳細を求人の下へ置く。対象は所属する組織の求人に届いた応募だけとする
- **詳細は応募時点の写しを出す**。現在のプロフィールの値は出さない
- 取り消された応募も一覧・詳細に出し、状態で区別する
- 判定を `CandidateProfile.visible_to(organization)` へ置き換える
- `applied_organizations` は、**その組織へ応募中（`submitted`）の場合だけ**見える
- **取り消した応募では見えない**
- 添付の可否（`documents_visible_to?(organization)`）も同じ判定に従う
- 現在のプロフィールへの導線は、見られるときだけ出す
- 応募を経由しない候補者の一覧・検索は作らない

## 理由

写しを出すのは、応募の後にプロフィールが変わっても、
企業が「応募のときに渡された内容」で判断できるようにするためである。
現在の値を出すと、求職者が職歴を消した後で選考が進み、
何を見て判断したのかが双方から分からなくなる。

取り消された応募を隠さないのは、選考を進める判断に関わるためである。
一覧から消すと、企業側は「応募がなかった」と読む。

取り消した場合に現在のプロフィールを見えなくするのは、
`applied_organizations` が「応募した企業に見せる」という意思表示だからである。
応募を取り消した相手に、その意思は残っていない。
一方、応募時点の写しは残る。それは取消の前に渡されたものであり、
渡した事実まで取り消せるわけではない。

添付を同じ判定に従わせるのは、
プロフィールが見えないのに履歴書だけ取れる状態を作らないためである。

導線を出し分けるのは、押しても 404 になるリンクを出さないためである。

応募を経由しない一覧・検索を作らないのは、ADR 0030 と同じ理由である。
「応募した企業に見せる」と「探されて一覧に並ぶ」は、同じ同意ではない。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 企業に現在のプロフィールを見せる | 求職者が後から消した内容で選考が進み、何を見たか分からなくなる |
| 取り消した応募を一覧から消す | 企業側は「応募がなかった」と読む |
| 取消後も `applied_organizations` を開いたままにする | 「応募した企業に見せる」意思は、取消の時点で残っていない |
| 取消で応募時点の写しも見えなくする | 渡した事実まで取り消すことになる。選考の記録が消える |
| 添付だけ別の条件にする | プロフィールが見えないのに履歴書だけ取れる状態ができる |
| 判定を経路ごとに書く | 書き忘れた経路が、そのまま個人情報への入口になる |

## 影響

- `CandidateProfile.visible_to_organizations`（引数なし）はなくなった。
  呼び出し側は組織を渡す
- 応募が増えると、`applied_profile_ids` の副問い合わせが効く範囲が広がる。
  索引は `job_applications` の外部キーにある。件数が増えた場合の観測は P11 で行う
- 選考の状態（書類選考・面接など）は P8 で扱う。
  そこで「選考中は取消後も見える」といった要件が出た場合は、この判定を見直す
- 応募者の絞り込み・並べ替えは持たない
- 企業側から応募者へ連絡する手段はまだない（P9）
