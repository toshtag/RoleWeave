# ADR 0017: 求人の審査を組織の管理者が行い、遷移をモデルへ閉じる

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0016 で、求人の公開状態を 1 つのレコードの `status` として持つことを決め、
「状態を増やすタスクは、`STATUSES` と遷移の規則を同時に足す」と記録した。

P4 の完了条件は「公開申請と審査を経て公開できる」を含む。

「審査」を誰が行うかは、このプロジェクトの前提に依存する。
自己ホスト可能な OSS として配布するため、
インスタンスを動かしているのは求人を出す組織自身であることが多い。
外部の運営者がすべての求人を審査する形は、その前提に合わない。

## 決定

- 状態は `draft` / `pending_review` / `published` / `rejected` の 4 つとする
- 許された遷移を `JobPosting::TRANSITIONS` へ持つ
  - `draft` → `pending_review`
  - `rejected` → `pending_review`
  - `pending_review` → `published`
  - `pending_review` → `rejected`
- 遷移の判断はモデルが持つ（`JobPosting#transition_to`）
- 許されていない遷移は例外にせず、`false` を返して何も変えない
- 公開申請は、その組織の所属であれば役割を問わずに行える
- 承認と差し戻しは、その組織の `owner` だけができる
- 編集できるのは `draft` と `rejected` の求人だけとする
- 公開状態を変える経路は、編集とは別の resource として置く
- 運営者（`users.operator`）による審査は行わない

## 理由

審査を組織の管理者が行うのは、自己ホストの前提に合うためである。
外部の運営者が審査する形にすると、
自分の会社の求人を出すために別の誰かの承認を待つことになる。

申請を役割で分けないのは、日々の作業が管理者の手を経ずに進むようにするためである。
下書きを書いて申請するところまでは、担当者が自分で進められる。

承認と差し戻しを `owner` に限るのは、公開が組織の対外的な表明だからである。
これは ADR 0013 で「組織の構成を変える操作」を `owner` に限ったのと同じ考え方による。
ADR 0011 で「役割の細分化は、制限する操作が決まってから足す」としていたが、
役割を増やす必要はなかった。`owner` と `member` の 2 つで足りている。

遷移をモデルへ閉じるのは、経路が増えたときに規則が分かれないためである。
Controller ごとに「この状態からなら通す」と書くと、
経路の数だけ規則の写しができる。

許されていない遷移を例外にしないのは、画面から来る操作が競合しうるためである。
承認と差し戻しが同時に届いたとき、後から来た方は失敗として扱えば足りる。
例外にすると、競合が 500 として現れる。

編集できる状態を限るのは、申請中と公開中の内容が
審査や公開の後で勝手に変わらないようにするためである。
審査した内容と公開された内容が違う状態は、審査の意味を失わせる。

経路を分けるのは、同じ経路にすると編集の権限がそのまま公開の権限になるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 運営者が審査する | 自己ホストの前提に合わない。自社の求人に他人の承認が要る |
| 申請も `owner` に限る | 日々の作業がすべて管理者を経由する |
| 審査のための役割を新設する | `owner` と `member` で足りている。使い道の薄い役割が増える |
| 遷移を Controller ごとに書く | 経路の数だけ規則の写しができる |
| 許されない遷移を例外にする | 操作の競合が 500 として現れる |
| 公開中の求人を編集できるようにする | 審査した内容と公開された内容が食い違う |
| 公開状態を編集と同じ経路で扱う | 編集の権限がそのまま公開の権限になる |

## 影響

- 公開中の求人を直したい場合は、いったん差し戻す必要がある。
  停止（P4-T3）を足した後は、停止してから直す形も選べるようになる
- 差し戻しの理由を記録していない。差し戻された側は、理由を別の手段で知る必要がある
- 公開状態の変更は、まだ履歴として残らない（P4-T4）
- 審査を待つ求人を管理者へ知らせる仕組みはない。一覧を見て気付く形である
- P4-T1 の負の検証で残っていた「状態をフォームから受け取れても検出されない」は、
  状態が 4 つになったことで検出できるようになった
