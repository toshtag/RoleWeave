# ADR 0007: ログイン状態をデータベースのレコードとして持つ

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0005 と ADR 0006 で、アカウントの識別子とパスワードの保存方式を決めた。
次に必要なのは、認証に成功したあとの状態をどこに持つかである。

P2 の対象範囲には「セッション保護」と「認証イベント記録」が含まれる。
また P2 以降では、パスワード再設定の完了時に他の端末のログインを切る、
不審なログインを利用者へ知らせる、といった要求が現れる。

セッションの持ち方は後から変える費用が高い。
方式を変えると、その時点でログインしている全員がログアウトする。

## 決定

- ログイン状態は `sessions` テーブルのレコードとして持つ
- `sessions` は `user_id` を持ち、アカウントへ従属する。
  アカウントの削除でセッションも削除する。外部キーを張る
- ブラウザーへ渡すのは、セッションのレコード ID を署名付き Cookie へ入れたものだけとする
- Cookie は `httponly` と `same_site: :lax` を付ける
- 同じアカウントで複数のセッションを持てる
- 現在のセッションは `ActiveSupport::CurrentAttributes`（`Current.session`）へ置く
- 認証は `User.authenticate_by` を使い、`find_by` と `authenticate` を自分で組み合わせない
- ログインの失敗理由を画面で区別しない
- ログアウトは `DELETE` で行う

## 理由

セッションをレコードにするのは、サーバー側から無効にできる状態を作るためである。
Cookie にアカウント ID だけを入れる方式では、
発行済みの Cookie を後から無効にする手段がない。
パスワードを変えても、盗まれた Cookie はそのまま使える。

外部キーを張るのは、参照先のないセッションを残さないためである。
アカウントを消した後にセッションだけが残ると、
`Current.user` が `nil` になる経路が増え、扱いが場所ごとに分かれる。

Cookie へ ID だけを入れるのは、ブラウザー側に判断材料を置かないためである。
署名を付けるのは、値の差し替えを検出するためである。
`httponly` を付けるのは、JavaScript から読めると XSS がそのまま乗っ取りになるためである。
`same_site: :lax` を付けるのは、別サイトからの遷移で Cookie を送らないためである。

複数のセッションを許すのは、端末ごとにログインできるようにするためである。
1 つに制限すると、別の端末でログインするたびに元の端末が切断される。

`CurrentAttributes` を使うのは、Model や View からも同じ値を参照するためである。
Controller のインスタンス変数に置くと、参照できる範囲が Controller と View に限られる。
`CurrentAttributes` はリクエストの終わりに自動で消えるため、
次のリクエストへ前の利用者の状態が残らない。

`authenticate_by` を使うのは、メールアドレスの存在の有無を応答時間から
読み取れないようにするためである。
`find_by` の結果が `nil` のときにパスワードの照合を省くと、
存在しないメールアドレスへの応答だけが速くなる。

失敗理由を区別しないのは、区別するとログイン画面が
「そのメールアドレスが登録されているか」を調べる道具になるためである。

ログアウトを `DELETE` にするのは、`GET` で状態が変わると
先読みやリンクの巡回だけでログアウトが起こるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| Cookie にアカウント ID を入れる | 発行済みの Cookie を後から無効にできない |
| Rails の暗号化セッション Cookie だけを使う | 同上。サーバー側に無効化の手段が残らない |
| セッションを Redis などの外部ストアへ置く | 初期段階で Redis を必須にしない（README の技術スタック方針） |
| アカウントごとに 1 つのセッションへ制限する | 別の端末でログインするたびに元の端末が切断される |
| 失敗理由を項目ごとに分けて伝える | ログイン画面が登録の有無を調べる道具になる |
| `find_by` と `authenticate` を自分で組み合わせる | 存在しないメールアドレスへの応答だけが速くなる |
| ログアウトを `GET` のリンクにする | 先読みやリンクの巡回だけでログアウトが起こる |

## 影響

- ログインのたびに `sessions` へレコードが増える。
  期限切れのセッションを消す仕組みは、有効期限を決めるタスクで合わせて設計する
- リクエストごとに `sessions` の読み出しが 1 回増える
- 認証イベントの記録は、このレコードへ属性を足す形で実装できる
- Cookie の `secure` 属性は、この ADR では扱わない。
  HTTPS を前提にする範囲は、セッション保護のタスクで決める
- セッションの有効期限を持たないため、現時点では明示的にログアウトするまで有効である
