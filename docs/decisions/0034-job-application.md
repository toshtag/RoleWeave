# ADR 0034: 応募は時点の写しを持ち、同じ求人へは 1 度だけとする

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P7 の完了条件は「公開求人へ応募できる」「同じ求職者が同じ求人へ二重応募できない」
「応募時点の求人とプロフィールが保存される」を含む。

求人は後から変わる。編集・差し戻し・停止で、内容も状態も変わる（ADR 0017、ADR 0018）。
プロフィールも後から変わる。職歴を消すことも、公開範囲を閉じることもできる（ADR 0030）。

応募は「そのとき何を見て、何を出したか」の記録である。

Rails は `RoleWeave::Application` を持つ。
モデルを `Application` と名付けると、名前の解決が読み手にとって曖昧になる。

## 決定

- 応募のモデル名を **`JobApplication`**（表は `job_applications`）とする
- 応募できるのは公開中（`published`）の求人だけとする
- 同じプロフィールから同じ求人へ 2 件目を作れない。一意索引でも拒否する
- **応募時点の求人とプロフィールを JSON（`jsonb`）として保存する**
- 保存する内容は `ApplicationSnapshot` の 1 か所が決める
- 写しは作成時に固定する。モデルの `before_validation` で書き、Controller では書かない
- **希望年収は、本人が見せる設定にしているときだけ写す**
- 内部の識別子は写しへ含めない
- 添付は名前・大きさ・形式だけを写す。実体は Active Storage が持つ
- 状態は `submitted` と `withdrawn` の 2 つとする
- 応募先・応募元は作成後に変更できない

## 理由

写しを持つのは、現在の値を出すと双方が確かめられなくなるためである。
企業側は「応募時に見た経歴」を確かめられず、
求職者は「自分が出した内容」を確かめられない。
求人の題名が変わった後で「この求人へ応募した覚えはない」となる状態を避ける。

写しをモデルへ置くのは、応募を作る経路が増えても写し忘れが起こらないようにするためである。
Controller に書くと、別の経路（管理画面、取り込み）を足したときに抜ける。

希望年収を出し分けるのは、応募したことと、希望年収を明かすことが
別の判断であるためである（ADR 0030 で同じ理由から設定を分けた）。
応募の操作が、その設定を上書きしてはならない。

内部の識別子を含めないのは、別の環境へ移したときに意味を持たず、
「応募時に何を見たか」の説明にもならないためである。

二重応募を拒否するのは、同じ求人に同じ人の応募が複数並ぶと、
企業側がどれを見ればよいか判断できないためである。
検証だけでは同時の送信をすり抜けるため、一意索引も置く。

取り消した応募が残っていても、同じ求人へは応募し直せない。
記録が残る以上、2 件目は同じ問題（どれを見ればよいか）を作る。
やり直したい場合の扱いは、取消を作るタスク（P7-T2）で決める。

公開中に限るのは、下書きや停止中の求人へ応募できると、
まだ募集していない仕事へ応募が届くためである。

`JobApplication` と名付けるのは、`Application` が Rails 自身の名前と重なるためである。
読み手が「どちらの Application か」を毎回考えることになる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 応募から現在の求人・プロフィールを参照するだけにする | 後から変わり、応募時に何を見たかを双方が確かめられない |
| 写しを Controller で作る | 応募を作る経路が増えたときに写し忘れる |
| 写しを別の表（正規化）で持つ | 応募のたびに全項目を行として複製することになり、構造も増える |
| 希望年収を常に写す | 応募の操作が、年収を明かさない設定を上書きする |
| 添付の実体を写しへ埋める | 応募のたびにファイルが複製される |
| 二重応募を検証だけで拒否する | 同時の送信をすり抜ける |
| 取消後の再応募を許す | 同じ求人に同じ人の応募が複数並び、どれを見ればよいか判断できない |
| モデル名を `Application` にする | Rails 自身の `RoleWeave::Application` と紛らわしい |

## 影響

- 応募の一覧・取消・状況表示は P7-T2 で扱う
- 企業側から応募を見る経路は P7-T3 で作る。
  そこで `CandidateProfile.visible_to_organizations`（ADR 0030）の扱いを決める
- 志望動機などの自由記述は持たない。必要になった時点で足す
- 求人は応募がある限り削除できない（`dependent: :restrict_with_error`）。
  求人を削除する経路は現時点でない
- プロフィールを削除すると応募も消える。
  企業側に残す記録は、応募の写しではなく応募イベント（P7-T4）が持つ
- 写しは `jsonb` である。中身の検索は現時点で行わない
