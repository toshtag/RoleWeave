# ADR 0030: プロフィールを既定で非公開とし、判定を 1 か所へ置く

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P6 の完了条件は「公開範囲を設定できる」を含む。

ここまで、プロフィール・職歴・学歴・スキル・希望条件は本人しか読めない。
企業側から見える経路がない。

ADR 0026 に「どこから見えるかを最初から決めておかないと、
後から公開範囲を足すときに『すでに見えていたもの』を隠せない」と記録した。
いまはまだ何も見えていない。範囲を決めるのはこの時点が最も安い。

ADR 0029 に「希望年収は、職歴や学歴と同じ扱いで企業へ渡してよい情報ではない」と記録した。

応募（P7）はまだない。

## 決定

- 公開範囲を `candidate_profiles.visibility` として持つ。
  値は `closed` / `applied_organizations` / `all_organizations`
- **既定値は `closed` とする。**設定しなければ誰にも見えない
- 希望年収の公開を `desired_salary_visible` として別に持つ。既定値は偽
- 見える・見えないの判定は `CandidateProfile.visible_to_organizations` だけが持つ
- 見えないプロフィールは 404 とする。403 とは分けない
- 企業側の経路は詳細（`/:locale/organizations/:id/candidate_profiles/:id`）だけとし、
  **一覧を作らない**
- `applied_organizations` はこの時点では誰にも見えない。
  そのことを設定画面に明示する
- 企業側の詳細に `noindex, nofollow` を出す
- 公開範囲の設定は、プロフィールの編集とは別の画面へ置く

## 理由

既定を `closed` にするのは、既定値が事実上の全体の設定になるためである。
「公開」を既定にすると、設定を知らない利用者の個人情報が出る。
逆にしても失うのは「見つけてもらう機会」であり、取り返しがつく。
出てしまった個人情報は取り返しがつかない。

判定を 1 か所へ置くのは、経路ごとに条件を書くと
書き忘れた経路がそのまま個人情報への入口になるためである。
組織側の経路は `visible_to_organizations` を通してしかプロフィールを引かない。

404 とするのは、403 と分けると
「その ID のプロフィールが存在すること」だけが分かるためである。
ID を順に試せば、登録されている求職者の数が分かる（ADR 0013、ADR 0020 と同じ理由）。

一覧を作らないのは、候補者検索が P6 の非目標であるためだけではない。
一覧があること自体が、公開範囲の意味を変えてしまう。
「求人を出している企業に見せる」と「探されて一覧に並ぶ」は、
利用者から見て同じ同意ではない。
探せる仕組みを作るときは、そのための同意を別に取る。

希望年収を別に扱うのは、応募先との交渉の材料であるためである。
先に見えていると、その金額が上限として扱われ、交渉の余地がなくなる。
ほかの項目と同じ設定にまとめると、プロフィールを見せるという判断が
そのまま希望年収を明かす判断になる。

`applied_organizations` を選べるようにしておくのは、
応募ができたときに設定を変えずに済むようにするためである。
いま選んでも誰にも見えないことを、設定画面へ明示する。
書かないと、見えないことが不具合に見える。

設定を別の画面へ置くのは、ほかの項目と同じ画面にすると
書き換えのついでに範囲が変わりうるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 既定を公開にする | 設定を知らない利用者の個人情報が出る。取り返しがつかない |
| 経路ごとに公開範囲の条件を書く | 書き忘れた経路が、そのまま個人情報への入口になる |
| 見えないプロフィールを 403 にする | ID の総当たりで、登録されている求職者の数が分かる |
| 候補者の一覧を作る | 「見せる」と「探される」は同じ同意ではない |
| 希望年収をほかの項目と同じ設定にまとめる | プロフィールを見せる判断が、そのまま年収を明かす判断になる |
| `applied_organizations` を今は選べなくする | 応募ができたときに、全員が設定を変え直すことになる |
| 公開範囲をプロフィールの編集画面に混ぜる | 書き換えのついでに範囲が変わりうる |
| 項目ごとに細かく公開範囲を持つ | 設定が増えるほど、利用者は既定のまま使う。既定の設計のほうが効く |

## 影響

- `applied_organizations` は、応募（P7）ができるまで誰にも見えない。
  P7 で `visible_to_organizations` を拡張する。拡張する場所はここ 1 か所である
- 企業側からプロフィールへ到達する導線は、この時点では存在しない。
  ID を知っていれば開けるが、ID を知る経路がない。
  応募ができたときに、応募の一覧から開ける
- 公開範囲を `all_organizations` にすると、求人を出しているかに関わらず、
  いずれかの組織に所属する利用者であれば開ける。
  「求人を掲載している企業」への限定は行っていない。
  組織は求人を出すために作られるためである
- 削除・匿名化（P6-T8）では、公開範囲によらず消えることを保証する
- エクスポート（P6-T7）には公開範囲の設定も含める
