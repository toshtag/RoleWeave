# ADR 0053: 0.x で出し、配るのはソースと手順に限る

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P12 の完了条件は「v0.1.0 のタグとリリース手順が存在する」を含む。

v0.1.0 の範囲は P0 から P12 までとし、
スカウトおよび汎用外部連携を必須条件にしない。

非目標に「常設公開環境の構築」「マネージドホスティングの提供」
「商用サポートの提供」がある。

版を示すものが何もない状態では、評価する人は
「どの時点のものを見ているか」をコミットの識別子でしか言えない。

## 決定

- [Semantic Versioning](https://semver.org/lang/ja/) に従う
- **最初のリリースを `v0.1.0` とする。`1.0.0` にしない**
- `0.x` の間は、機能の追加と互換性のない変更を同じ位置で上げる
- `1.0.0` は、自己ホストの利用者が本番で使える状態になってから付ける
- タグは注釈付き（`git tag -a`）で作る
- `CHANGELOG.md` へ、**入っているもの・入っていないもの・既知の制限**を書く
- GitHub の Release の公開は、維持している人が手で行う
- **配るのはソースと手順に限る。**コンテナイメージも常設環境も出さない
- タグは消さない。問題が見つかったら次の版で直す

## 理由

`0.1.0` から始めるのは、**本番運用を保証できないためである**。
機能はそろっているが、production での測定をしていない（ADR 0050）。
アクセシビリティの検証にも未了がある（`docs/known-gaps.md`）。
`1.0.0` は「使ってよい」という約束であり、いま出せる約束ではない。

既知の制限を `CHANGELOG.md` へ書くのは、評価する人が
**先に限界を知って**判断できるようにするためである。
使い始めてから気付く形にすると、評価にかけた時間が無駄になる。

入っていないものを書くのは、あることを期待して探す時間を減らすためである。
候補者の検索は「未実装」ではなく「持たない」である（ADR 0030）。

Release の公開を自動にしないのは、公開が取り消せない操作だからである。
タグは作れても、公開の判断は人が行う。

配るものをソースと手順に限るのは、非目標に沿うためである。
コンテナイメージを配ると、その更新と脆弱性への対応を引き受けることになる。
個人が維持する OSS として、引き受けられる範囲を超える。

タグを消さないのは、消すとその版を取得していた人の参照が壊れるためである。
問題があったことは `CHANGELOG.md` へ残す。
履歴から消すと、同じ問題を踏んだ人が原因にたどり着けない。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| `1.0.0` から始める | 本番運用を保証できない。約束できないことを約束することになる |
| 既知の制限を書かない | 使い始めてから気付く形になり、評価の時間が無駄になる |
| 入っていないものを書かない | あることを期待して探す時間が生まれる |
| Release を自動で公開する | 取り消せない操作を人の判断なしに行うことになる |
| コンテナイメージを配る | 更新と脆弱性への対応を引き受けることになる |
| 常設の公開環境を用意する | 非目標である。運用の責任が生まれる |
| 問題のあった版のタグを消す | 取得していた人の参照が壊れる |

## 影響

- `0.x` の間、利用者は版を上げるときに移行の手間を見込む必要がある
- `1.0.0` を出す条件は、production での測定とアクセシビリティの検証を含む。
  P13 以降のどこで満たすかは決まっていない
- GitHub の Release を公開しない限り、タグだけが版の目印になる
- コンテナイメージがないため、利用者は自分で構築する。
  手順は README にある
