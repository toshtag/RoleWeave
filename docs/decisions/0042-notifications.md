# ADR 0042: アプリ内通知は設定で止めず、メールに中身を書かない

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P9 の完了条件は「アプリ内通知とメール通知が配信される」を含む。

会話（ADR 0041）は開かない限り気付けない。
選考のステージが変わっても（ADR 0038）、応募者には伝わらない。

通知は外（SMTP）へ出る。
応募の通知（ADR 0037）で「失敗しても元の操作が巻き戻らない」ことを決めている。

メールを受け取りたくない利用者もいる。

## 決定

- アプリ内通知（`notifications`）を利用者ごとに作る
- 種類は `message_received` と `stage_changed` の 2 つとする
- **アプリ内通知は設定によらず作る。**設定が止めるのはメールの送信だけとする
- メールは `after_commit` の後に `deliver_later` で送る
- 利用者ごとに `email_notifications` を持つ。既定は受け取る
- 通知の一覧は開いた時点で既読にする
- 未読の件数を共通ヘッダーへ出す
- 選考の状況の変化は**応募者へだけ**知らせる
- メッセージの通知の宛先は、会話の参加者から自分を除いたすべてとする
- **メールの本文に中身（メッセージの本文・段階・評価・経歴）を書かない**

## 理由

アプリ内通知を設定で止めないのは、止めると後から見返す手段がなくなるためである。
メールは受信箱の問題であり、アプリの中の記録とは別のことである。
「メールは要らないが、ログインしたときには知りたい」を選べるようにする。

`after_commit` で積むのは、通知の失敗でメッセージの送信が巻き戻らないようにするためである
（ADR 0037 と同じ理由）。相手に届かないことと、送った事実が消えることは別である。

選考の状況を企業側へ知らせないのは、企業側が自分たちで動かしているためである。
自分が押した操作の通知が自分に届いても、雑音にしかならない。

メッセージの通知を所属者すべてへ送るのは、担当者（ADR 0039）が
決まっていない応募があるためである。誰も気付かない状態を作らない。

メールに中身を書かないのは、メールが転送も保存もされる経路であるためである。
段階（内定・不採用）を件名や本文へ書くと、採否が受信箱に残り続ける。
本人以外が見る端末で通知が表示されることもある。
「何かが起きた」ことだけを伝え、中身はアプリで読んでもらう。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 設定でアプリ内通知も止める | 後から見返す手段がなくなる |
| メールを既定で送らない | 気付かれないまま選考が止まる |
| メールの本文にメッセージを載せる | 受信箱へ個人的なやり取りが残り続ける |
| 段階を件名に書く | 採否が受信箱と通知の表示に残る |
| 通知を同じトランザクションで送る | メールが送れないだけでメッセージが失敗する |
| 企業側へも状況の変化を通知する | 自分が押した操作の通知が届き、雑音になる |
| 担当者だけへ通知する | 担当者が決まっていない応募が誰にも気付かれない |

## 影響

- 通知の種類ごとの細かい設定はない。増やすかは、種類が増えてから判断する
- ダイジェスト（まとめて 1 通）はない。件数が増えると受信箱が埋まりうる
- 配信の失敗は記録していない。記録と再送は P9-T3 で扱う
- リアルタイムの更新はない。読み込み直しで最新になる
- 通知の保存期間は未定（P10）。件数は増え続ける
- `users.email_notifications` はエクスポート（ADR 0032）へ含める。
  本人が決めた設定であり、本人のデータである
