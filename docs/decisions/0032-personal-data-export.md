# ADR 0032: エクスポートは JSON とし、出す列と出さない列を明示する

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P6 の完了条件は「自分のデータをエクスポートできる」を含む。

エクスポートは、削除・匿名化（P6-T8）の前提でもある。
消す前に手元へ残せなければ、削除は「失う」だけの操作になる。

出してはならないものがある。
パスワードのハッシュ、セッション、確認や再設定の token である。
本人へ返す意味がなく、渡った先で悪用されうる。

項目は今後も増える。
新しい列が自動的に出るのも、自動的に出ないのも、どちらも事故になりうる。
前者は、出すつもりのない情報が出る。後者は、本人のデータが持ち出せない。

## 決定

- 形式は JSON とする。新しい依存を足さない
- 組み立ては `ProfileExport` の 1 か所が持つ
- `Content-Disposition: attachment` で返す
- **パスワードのハッシュ・セッション・token を含めない**
- 運営者かどうか（`users.operator`）も含めない
- 内部の識別子（`id`、`user_id`）を含めない
- 添付はファイルそのものではなく、名前・大きさ・形式だけを含める
- 出す列（`EXPORTED_COLUMNS`）と出さない列（`EXCLUDED_COLUMNS`）を明示する。
  **どちらにも入っていない列があれば、テストが落ちる**
- 出さない列には、出さない理由を書く
- エクスポートできるのは本人だけとする。経路は ID を受け取らない

## 理由

JSON を選ぶのは、依存を足さずに構造のまま出せるためである。
CSV は表が複数あるデータを 1 つのファイルへ収められない。
ZIP でまとめる案は `rubyzip` の追加を要する。
自己ホストの利用者が読む前提であれば、JSON で足りる。

`Content-Disposition: attachment` で返すのは、
ブラウザーの中で開くと、そのまま履歴やキャッシュへ残りうるためである。

パスワードのハッシュを外すのは、渡った先で総当たりの材料になるためである。
本人が自分のパスワードを知っている以上、ハッシュを返す意味がない。

運営者かどうかを外すのは、このサーバーの運用の情報であり、
本人のデータではないためである。

内部の識別子を外すのは、本人にとって意味がないためである。
別のサーバーへ取り込むときにも、この値は使えない。

添付の中身を含めないのは、JSON へ埋めると
base64 で 1.33 倍に膨らみ、10 MB の添付が 1 つのテキストとして扱いにくくなるためである。
本人は添付を自分の画面からそのままダウンロードできる。
エクスポートには、何を添付していたかの記録として名前・大きさ・形式を残す。

列の網羅をテストで固定するのは、列が増えるためである。
「出す列の一覧」だけを持つと、増えた列は黙って出ない。
「除外する列の一覧」だけを持つと、増えた列は黙って出る。
両方を持ち、どちらにも入っていない列があればテストが落ちるようにすれば、
増やした人が「出すか出さないか」を必ず決めることになる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| CSV で出す | 表が複数あるデータを 1 つのファイルへ収められない |
| ZIP でまとめる | `rubyzip` の追加を要する |
| 添付の中身を base64 で埋める | 1.33 倍に膨らみ、テキストとして扱いにくくなる |
| 出す列だけを一覧にする | 増えた列が黙って出ない。本人のデータが持ち出せない |
| 除外する列だけを一覧にする | 増えた列が黙って出る |
| モデルの `as_json` をそのまま使う | 列が増えるたびに、意図しない情報が出る |
| 非同期で作ってメールで送る | メールの経路へ個人情報が乗る。同期で返せる大きさである |

## 影響

- 表を足したときは、`ProfileExport` へ出すかどうかを書く必要がある。
  `users` と `candidate_profiles` の列はテストが網羅を確かめる。
  従属する表（職歴・学歴・スキル・希望条件）は一覧が固定である
- 応募・メッセージ（P7 以降）ができたら、エクスポートへ含めるかを決める
- エクスポートは同期で返す。データが大きくなった場合は、
  応答時間が問題になりうる。現時点では 1 人あたりの件数が小さい
- 削除・匿名化（P6-T8）の画面では、先にエクスポートへ導く
