# ADR 0041: 会話は応募に紐づけ、既読はメッセージごとに持つ

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P9 の完了条件は「応募に紐づく会話でメッセージを送受信できる」
「無関係な利用者が会話を参照できない」「メッセージの既読が記録される」を含む。

企業から応募者へ連絡する手段がなかった。
面接の予定（ADR 0040）を入れても、応募者には届かない。

会話の相手をどう決めるかは、この仕組みの性質を決める。
相手を自由に選べるようにすると、応募と関係のない連絡が発生する。

## 決定

- 会話（`conversations`）は**応募に 1 つ**とする
- 参加できるのは、応募者本人とその組織の所属者だけとする
- 判定を `Conversation.visible_to(user)` の 1 か所へ置く
- 会話は最初のメッセージが送られたときに作る
- **取り消された応募では新しいメッセージを送れない。読むことはできる**
- メッセージの内容は後から変えられない
- 送信者を削除してもメッセージは残す。誰が書いたかは失われる
- 既読（`message_reads`）は**メッセージごとに行を持つ**
- 自分が送ったメッセージは既読の対象にしない
- 会話を開いた時点で、相手のメッセージを既読にする

## 理由

会話を応募に紐づけるのは、相手を応募が決めるためである。
利用者が相手を検索して連絡できる仕組みにすると、
応募を経由しない接触（スカウト、勧誘）が生まれる。
それは P6 で「探されない」ことを選んだ設計（ADR 0030）と食い違う。

取り消された応募で送れなくするのは、応募者がその選考から降りているためである。
一方、読めなくはしない。やり取りは選考の記録であり、双方に残る必要がある。

メッセージを変えられなくするのは、相手が読んだものと食い違うためである。
「言った・言わない」を作らない。

送信者を削除してもメッセージを残すのは、相手から見てやり取りが消えないためである。
片方が退会したら会話が空になるのでは、記録にならない。

既読をメッセージごとに持つのは、誰がどれを読んだかを正確に言えるようにするためである。
会話ごとの「最後に読んだ時刻」だけを持つと、
後から届いたメッセージとの前後関係で曖昧になる。
行が増えるが、扱う件数はやり取りの規模に収まる。

自分のメッセージを既読の対象にしないのは、
自分で書いたものを「読んだ」と記録しても意味がないためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 相手を選んで会話を始められるようにする | 応募を経由しない接触が生まれる。ADR 0030 の設計と食い違う |
| 取消後も送れるようにする | 応募者は選考から降りている |
| 取消後は読めなくする | 選考の記録が双方から消える |
| メッセージを編集・削除できるようにする | 相手が読んだものと食い違う |
| 送信者の削除でメッセージも消す | 片方が退会すると会話が空になり、記録にならない |
| 既読を会話ごとの時刻で持つ | 後から届いたメッセージとの前後関係が曖昧になる |
| 既読を送信者だけに見せる | まず記録することを優先し、見せ方は必要になってから決める |

## 影響

- 通知（アプリ内・メール）は P9-T2 で扱う。いまは開かない限り気付けない
- メッセージの添付は P9-T3 で扱う
- リアルタイムの更新はない。読み込み直しで最新になる
- 会話の一覧（応募をまたぐ受信箱）はない。応募ごとに開く
- メッセージの保存期間は未定（P10）
- 既読の行は、メッセージ数 × 参加者数まで増えうる。観測は P11 で行う
