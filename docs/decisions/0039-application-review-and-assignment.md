# ADR 0039: 評価は応募者に見せず、担当者は所属者に限る

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P8 の完了条件は「評価とコメントを記録できる」を含む。
対象範囲は「担当者」「評価」「コメント」を含む。

選考は複数人で行う。誰がどう見たかが残らないと、
ステージを進めた理由（ADR 0038）が後から読めない。

評価とコメントは、応募者について社内で言葉にしたものである。
公開範囲（ADR 0030）やエクスポート（ADR 0032）は
「応募者が自分の情報をどう扱うか」の仕組みであり、
社内の評価はそこに含まれない。

## 決定

- 評価（`application_reviews`）を応募へ従属させる
- **1 つの応募に複数の評価を残せる**
- 評価は 1〜5 の整数、コメントは自由記述。どちらも任意とする
- ただし**両方が空の記録は作れない**
- 記録した人（`reviewer`）を残す。削除しても記録は残し、参照を空にする
- 記録の内容は後から変えられない
- **評価は応募者に見せない。**求職者側の画面・エクスポート・応募の写しに現れない
- 読み書きできるのは、その組織の所属者だけとする
- 担当者（`job_applications.assignee`）を持たせる。組織の所属者に限る
- **担当者の変更の履歴は持たない**

## 理由

複数の評価を許すのは、選考の段階ごとに見る人が違うためである。
1 人 1 件に制限すると、面接のたびに書き換えることになり、
前の段階でどう見えていたかが消える。

両方が空の記録を作れないのは、何も伝えていない行が並ぶのを避けるためである。

記録を変えられなくするのは、「誰がいつどう見たか」という記録の意味を守るためである。
後から書き換えられると、判断の経緯ではなく現在の意見の一覧になる。

応募者に見せないのは、社内の評価が応募者に向けた文書ではないためである。
見せる前提にすると、書く側が率直に書けなくなり、記録としての意味が薄れる。
一方、見せないと決めた以上、**漏れないことをテストで固定する**必要がある。
求職者側の画面・エクスポート・応募の写しのそれぞれで確かめている。

担当者を所属者に限るのは、外部の利用者を担当にできると
応募が組織の外から扱われる状態になるためである。

担当者の履歴を持たないのは、完了条件が求めていないためである。
「誰が担当か」は現在の状態であり、変更の経緯が要る場面はまだ現れていない。
必要になった時点で、応募の記録（ADR 0037）へ足す。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 1 人 1 件の評価に制限する | 面接のたびに書き換えることになり、前の段階の見え方が消える |
| 評価を後から編集できるようにする | 判断の経緯ではなく、現在の意見の一覧になる |
| 評価を応募者にも見せる | 書く側が率直に書けなくなり、記録としての意味が薄れる |
| 評価の平均や集計を出す | 数値が独り歩きする。まず記録として残すことを優先する |
| 担当者を組織の外からも選べるようにする | 応募が組織の外から扱われる |
| 担当者の変更を履歴に残す | 要求がない。必要になった時点で応募の記録へ足す |

## 影響

- 評価の集計・並べ替えはない。件数が増えたときの読み方は、必要になってから決める
- 評価を応募者へ開示する要求（法令や運用）が出た場合は、
  「見せない前提で書かれた記録」をどう扱うかから決め直す必要がある
- 担当者への通知はない（P9）
- 応募を削除すると評価も消える。応募の記録（ADR 0037）には評価を含めない
- 評価の保存期間は未定（P10）
