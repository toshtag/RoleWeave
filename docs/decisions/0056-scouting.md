# ADR 0056: スカウトは 1 人 1 通、上限と配信停止で送りすぎを止める

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P13 の完了条件は「スカウトを送信でき送信上限が機能する」
「配信停止した候補者へ送信できない」を含む。

受信の許可（ADR 0055）は「探されてよい」の意思表示である。
**探されることと、何通も送られることは別である。**

上限がないと、1 つの組織が一覧のすべてへ送れる。
そうなると受信の許可を取り消す人が増え、仕組み自体が使われなくなる。

## 決定

- スカウト（`scouts`）は組織から候補者へ送る
- 送れるのは、探せる候補者（ADR 0055 の `searchable`）だけとする
- **同じ組織から同じ候補者へ 2 通目を送れない。**一意索引でも拒否する
- 送信の上限を**組織ごと・1 日ごと**に置く（50 通）
- 候補者は**組織ごとに**配信停止できる（`scout_blocks`）
- 止められるのは、**実際に送られてきた組織だけ**とする
- 送った内容は後から変えられない
- 受信はアプリ内通知とメールで知らせる。**メールの本文にスカウトの本文を書かない**
- 送信を監査ログ（ADR 0047）へ残す
- テンプレート（`scout_templates`）は組織で共有する
- **スカウトへの返信の経路を作らない**

## 理由

1 人 1 通に限るのは、追いかけを防ぐためである。
断られたことを「返事がない」と読み替えて何通も送る形は、
受け取る側から見れば嫌がらせと変わらない。
2 通目を送る手段がなければ、その状態は起こらない。

上限を組織ごと・1 日ごとに置くのは、一覧の全員へ一度に送る使い方を止めるためである。
**値（50 通）に強い根拠はない。**運用の実績に応じて見直す。

配信停止を組織ごとにするのは、「探されてよい」を保ったまま
特定の会社だけを止められるようにするためである。
全体を止めるしかない形にすると、1 社のために全部を閉じることになる。

止められるのを送られてきた組織だけに限るのは、
任意の組織を指定させると、存在する組織の一覧を外から作れるためである。

返信の経路を作らないのは、応募の会話（ADR 0041）と二重になるためである。
関心があるなら応募すればよく、そこに会話がある。
スカウトの側に別の会話を作ると、どちらで話しているかが分からなくなる。

メールに本文を書かないのは、通知（ADR 0042）と同じ理由による。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 同じ候補者へ何通でも送れる | 追いかけになる。受け取る側には嫌がらせと変わらない |
| 上限を置かない | 一覧の全員へ一度に送れる |
| 上限を利用者ごとに置く | 人を増やせば回避できる |
| 配信停止を全体だけにする | 1 社のために全部を閉じることになる |
| 任意の組織を止められるようにする | 存在する組織の一覧を外から作れる |
| スカウトへ返信できるようにする | 応募の会話と二重になる |
| メールへ本文を書く | 受信箱に内容が残り続ける |
| 送信の記録を残さない | 誰が誰へ送ったかを後から確かめられない |

## 影響

- 一度送ると、その候補者へは二度と送れない。取り消しもできない。
  画面で送る前に伝える
- 上限は 1 日単位である。日付が変わると回復する
- 配信停止は組織ごとに残る。受信の許可を取り消しても消えない
- スカウトは組織またはプロフィールの削除で消える。
  配信停止の記録は残す（止めたままにする）
- 有料プランによる上限の制御は行わない（P13 の非目標）
