# ADR 0003: エラー画面を静的 HTML とし、ロケールを元の URL から決める

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0001 で、利用者向けの URL は `/:locale/...` とし、表示言語の正本を URL とすることを決めた。
P1-T1 から P1-T4 で入口ページ、共通レイアウト、デザイン変数、言語切替が揃い、
通常の画面は日本語と英語のどちらでも成立する状態になった。

一方、例外時に返るのは Rails 生成時のままの `public/404.html` と `public/500.html` である。
これらは英語だけの汎用文言で、日本語の URL からたどり着いても日本語にならない。
P1 の完了条件は「404 とサーバーエラーの画面が表示される」ことを含む。

エラー画面には、通常の画面にはない制約がある。
500 は、アプリケーション側の描画に障害がある状況で表示される。
その状況でエラー画面が Controller、View、アセットパイプラインを使うと、
障害の原因がそのままエラー画面の表示不能につながる。
つまりエラー画面は「アプリケーションが正しく動くこと」を前提にできない。

同時に、エラー画面もどの言語で表示するかを決める必要がある。
ところが `ActionDispatch::ShowExceptions` は exceptions app を呼ぶ前に
`PATH_INFO` を `/404` や `/500` へ書き換えるため、例外処理中のパスにロケールは残っていない。

「エラー画面をどこまでアプリケーションから切り離すか」と
「切り離した先でどうやって言語を決めるか」は、
今後追加するすべてのエラー応答へ影響するため ADR として残す。

## 決定

- 404 と 500 は `public/` 配下の静的 HTML とする
- 日本語は拡張子を持たない `public/404.html`・`public/500.html` を正本とする
- 英語は `public/404.en.html`・`public/500.en.html` とする
- `public/404.ja.html`・`public/500.ja.html` は作らない
- 表示ロケールは `action_dispatch.original_path` の先頭セグメントから決める
- 書き換え後の `PATH_INFO` をロケール判定に使わない
- 対応外のロケールとロケールを持たない URL は、既定ロケールの日本語とする
- ロケールの適用は `I18n.with_locale` の中だけに閉じ、`I18n.locale` へ直接代入しない
- ロケールを決めた後は `ActionDispatch::PublicExceptions` へ委譲し、
  HTML 本文、status、Content-Type、HEAD、HTML 以外の形式の扱いを再実装しない
- エラー画面から Controller、View、通常のレイアウト、Propshaft、Importmap、
  JavaScript、外部フォント、CDN、画像、SVG を参照しない
- 各ページのスタイルは `style` 要素へインラインで持ち、4 ページで内容を一致させる
- エラー画面へ例外メッセージと backtrace を出さない
- exceptions app はすべての環境で同じものを設定し、
  実際に表示するかどうかは `consider_all_requests_local` と `show_exceptions` に任せる
- 400、406、422 は今回変更しない

## 理由

静的 HTML にするのは、500 が「アプリケーションの描画が失敗した後」に表示されるためである。
Controller と View を通す構成では、描画の失敗がエラー画面の描画の失敗も引き起こす。
静的ファイルであれば、アプリケーションの状態と無関係に読み出せる。

日本語を拡張子なしのファイルへ置くのは、`PublicExceptions` のフォールバック先がそこだからである。
`PublicExceptions` は `404.<locale>.html` を探し、なければ `404.html` を読む。
既定ロケールが日本語である以上、フォールバック先も日本語であるべきで、
`404.ja.html` を別に作ると同じ内容の HTML を 2 か所で保守することになる。

ロケール判定に元のパスを使うのは、例外処理中のパスがすでに書き換えられているためである。
`ShowExceptions` は `PATH_INFO` を `/404` へ書き換える直前に、
元のパスを `action_dispatch.original_path` へ保存する。判定できる情報はここにしかない。

先頭セグメントだけを見るのは、パス全体からロケール名を探すと
`/ja/en-training` のような日本語の URL が英語のエラー画面になるためである。

対応外のロケールを英語へ落とさないのは、既定ロケールを日本語とする設定と矛盾するためである。
`/fr/...` から英語が返ると、URL にも設定にも根拠のない言語が選ばれることになる。

`I18n.with_locale` を使うのは、`I18n.locale` への代入がスレッドに残るためである。
エラー画面のために設定した言語が、同じスレッドを使う次のリクエストへ漏れる。

`PublicExceptions` へ委譲するのは、エラー応答が HTML だけではないためである。
HEAD リクエスト、JSON 要求、ファイルが存在しない場合の `X-Cascade` の扱いは
すでに Rails 側にあり、自前で書き直せば Rails の更新に追随できない箇所が増える。
今回追加するのは、ロケールを決めて委譲するだけの薄いアダプターに限る。

スタイルをインラインで複製するのは、エラー画面がアセットパイプラインへ依存しないためである。
外部 CSS を読み込む構成では、アセットの配信に問題がある状況でエラー画面が素のまま表示される。
`application.css` との重複は、この独立性と引き換えに受け入れる。
値が分岐しないよう、4 ページで `style` の内容が一致することをテストで固定する。

環境ごとに exceptions app を切り替えないのは、
本番でだけ通る経路を作ると、その経路を検証する手段が本番しかなくなるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| `ErrorsController` による動的描画 | 500 の発生時に、失敗した描画経路へ再び依存する |
| catch-all route | 例外処理と通常のルーティングの責務が混ざる |
| 日英を 1 ページへ併記 | URL のロケールと表示言語が一致しなくなる |
| `Accept-Language` による判定 | 表示言語の正本を URL とする ADR 0001 の契約に反する |
| JavaScript による切替 | JavaScript が動かない状況でもエラー画面は表示する必要がある |
| `I18n.locale` への直接代入 | 設定した言語が後続のリクエストへ漏れる |
| `404.ja.html` の追加 | 同じ内容の HTML を 2 か所で保守することになる |
| 独自 Rack アプリでの応答組み立て | HEAD、JSON、`X-Cascade` の扱いを再実装することになる |

## 影響

- 対応言語を追加するときは、`public/<status>.<locale>.html` を追加する。
  アダプターは対応ロケール一覧を設定から受け取るため、コードの変更は要らない
- エラー画面の文言は i18n 辞書ではなく HTML が持つ。
  `config/locales/` を変更してもエラー画面は変わらない
- `application.css` のデザイン変数を変更したときは、エラー画面のインライン CSS も見直す。
  この 2 つは自動では同期しない
- エラー画面のスタイルを変更するときは、4 ページすべてを同じ内容へ揃える
- `lib/localized_public_exceptions.rb` は `config/application.rb` から明示的に読み込む。
  middleware が保持するため autoload と reload の対象にしない

この ADR は 400、406、422 の扱いを決めるものではない。
これらは Rails 生成時のページのままであり、利用者が実際に到達する経路が確認できた時点で、
同じ方式を適用するかどうかを別途判断する。
エラー通知、エラー監視、Request ID の表示、問い合わせ導線も、
それぞれ必要になったタスクで別途決定する。
