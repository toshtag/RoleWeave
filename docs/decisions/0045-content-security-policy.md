# ADR 0045: CSP を self から始め、nonce を使わない

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P10 の完了条件は「CSP と CSRF 保護が有効である」を含む。

`config/initializers/content_security_policy.rb` は生成時のままで、
すべてコメントアウトされていた。CSP は出ていなかった。

このアプリケーションは外部のスクリプトも外部の CSS も読み込まない。
Importmap と Propshaft で自前の資産だけを配る（ADR 0002）。

静的エラー画面（ADR 0003）は `style` 要素を持つ。
描画経路を通さずに読めることが要件であり、外部の CSS を使えない。

## 決定

- CSP を有効にし、既定（`default-src`）を `self` とする
- `object-src` と `frame-ancestors` を `none` にする
- `script-src` は `self` だけとする。**`unsafe-inline` も `unsafe-eval` も許さない**
- **nonce を使わない**
- `style-src` は `self` と `unsafe-inline` を許す
- 報告だけの動作（`report_only`）にはしない
- CSP・CSRF 保護・セッションの Cookie の属性をテストで固定する

## 理由

`self` から始められるのは、外部の資産を読み込まない構成だからである。
後から緩めるのは容易だが、緩い値から締めるのは難しい。
先に厳しくしておくと、外部の読み込みを足すときに必ず判断が要る。

nonce を使わないのは、インラインのスクリプトを書かない方針だからである。
nonce を用意すると「インラインを書いてよい」入口になる。
Importmap と Stimulus で足りている。

`style-src` に `unsafe-inline` を許すのは、静的エラー画面のためである。
これらは描画経路に障害がある状況でも読める必要があり、
外部の CSS も nonce も使えない。
スクリプトと違い、インラインの style から任意の処理は実行されない。

報告だけにしないのは、報告だけでは防いでいないためである。
「入れてある」と言えるだけの状態を避ける。

設定をテストで固定するのは、設定が静かに緩むためである。
誰かが `unsafe-inline` を足しても、画面は動く。動くから気付かない。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| CSP を入れない | 外部の資産を読み込まない構成で、入れない理由がない |
| 報告だけにする | 違反があっても防いでいない |
| nonce を使う | インラインのスクリプトを書いてよい入口になる |
| `style-src` も厳しくする | 静的エラー画面が読めなくなる |
| CSP の値をテストで固定しない | 緩めても画面は動く。動くから気付かない |
| `report-uri` で違反を集める | 収集先の運用が要る。自己ホストの前提と合わない |

## 影響

- 外部のスクリプト・CSS・フォント・画像を読み込めない。
  必要になった場合は、この ADR を更新したうえで許可する
- 別のサイトの枠へ埋め込めない（`frame-ancestors 'none'`）。
  埋め込みを許す要求が出た場合は、どこから許すかを決める
- CSP の違反は収集していない。ブラウザーの開発者ツールでしか見えない
- HSTS は `force_ssl` に委ねている。production でのみ有効である
- CSRF 保護は Rails の既定のままである。テストで有効を固定した
