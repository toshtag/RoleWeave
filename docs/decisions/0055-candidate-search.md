# ADR 0055: 候補者検索は「探されてよい」の明示的な許可の上でだけ行う

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P13 の完了条件は「受信を許可した候補者だけを検索できる」を含む。

**ADR 0030 で「候補者の一覧を作らない」と決めている。**
理由は「『応募した企業に見せる』と『探されて一覧に並ぶ』は、
利用者から見て同じ同意ではない」ためである。

一覧を作るなら、その同意を取る仕組みが要る。
取らずに一覧だけを作れば、ADR 0030 の判断を黙って覆すことになる。

## 決定

- 求職者の受信の許可（`candidate_profiles.scout_opt_in`）を追加する。**既定は false**
- 検索の対象は `CandidateProfile.searchable` が決める。
  **許可していて、かつ公開範囲が `closed` でない**プロフィールだけとする
- 検索できるのは、組織に所属する利用者だけとする
- 結果に出すのは**限られた項目**（表示名・所在地・希望職種・スキル名）とする
- 経歴・自己紹介・添付は結果に出さない。詳細は既存の判定（ADR 0036）に従う
- **検索したこと自体を監査ログ（ADR 0047）へ残す**
- タレントプールは**組織の中で共有**する
- プールへ入れられるのは、探せる候補者だけとする
- **プールの表示と件数も、その時点で探せる候補者だけとする。**
  入れた時点の許可ではなく、いまの許可で決める

## 理由

既定を false にするのは、公開範囲（ADR 0030）と同じ理由による。
既定値は事実上の全体の設定であり、
設定を知らない利用者が一覧へ並ぶ状態を作らない。

公開範囲が `closed` の場合に対象外とするのは、
2 つの設定が食い違ったときに**閉じている側を優先する**ためである。
「誰にも見せない」と言っている人が、検索の結果には並ぶ状態を作らない。

結果の項目を絞るのは、一覧が「探すための画面」であり、
「読むための画面」ではないためである。
経歴まで一覧に出ると、開かずに大量の個人情報を集められる。

検索したことを記録するのは、**探す行為そのものが個人情報に触れる**ためである。
誰がどの条件で探したかが残らないと、後から範囲を確かめられない。

プールを組織で共有するのは、担当者が変わったときに引き継げるようにするためである。
個人ごとに分けると、退職や異動のたびに失われる。

**表示の時点でも判定する**のは、入れる時点だけを見ると、
一度でも許可した相手に対しては取り消しが効かなくなるためである。
撤回できない同意は同意ではない。
「探されてよい」を取り消した人が、既に保存した組織の画面にだけ残る状態を作らない。

## ADR 0030 との関係

**ADR 0030 は覆していない。**
「同意なしに一覧へ並べない」という判断はそのまま維持している。
この ADR は、その同意を取る仕組みを足したうえで一覧を作るものである。

許可していない候補者にとっては、ADR 0030 の状態が続く。
一覧に並ばず、応募した企業からだけ見える。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 許可なしに一覧を作る | ADR 0030 の判断を黙って覆すことになる |
| 既定を true にする | 設定を知らない利用者が一覧へ並ぶ |
| 公開範囲が `closed` でも許可があれば出す | 2 つの設定が食い違ったまま、開いている側が勝つ |
| 一覧へ経歴も出す | 開かずに大量の個人情報を集められる |
| 検索を記録しない | 誰がどの条件で探したかを後から確かめられない |
| プールを個人ごとに持つ | 担当者が変わると引き継げない |
| 入れた時点の許可だけで表示し続ける | 取り消しが効かない。撤回できない同意になる |
| 探せなくなった候補者の所属を消す | 許可を戻しても組織側の作業が戻らない |
| 全文検索で経歴も探せるようにする | 一覧の項目を絞った意味がなくなる |

## 影響

- 許可していない候補者は、企業側の検索に**存在しない**。
  件数にも含まれない
- 受信の許可はエクスポート（ADR 0032）へ含める。本人が決めた設定である
- タレントプールは組織の削除で消える。保持期限の対象にはしない
- 探せなくなった候補者の所属は**行として残るが、企業側からは見えない**。
  許可を戻せば、また見える
- スカウトの送信は P13-T3 で扱う。**許可はしたが送られたくない**を分けるかは、そこで決める
- 検索の絞り込みは `ILIKE` による部分一致である。件数が増えた場合の性能は P11 の基準に従う
