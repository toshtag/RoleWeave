# ADR 0035: 応募の取消は記録を残し、同じ求人へは応募し直せない

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P7 の完了条件は「求職者が自分の応募を取消できる」を含む。
対象範囲は「応募履歴」「状況表示」も含む。

ADR 0034 で、応募は応募時点の写しを持ち、
同じ求人へは 1 度しか応募できないと決めた。
取消の扱いは、そのタスクでは決めていない。

取消を「行を消す」として実装すると、企業側から見て
「応募がなかったこと」になる。
すでに選考を始めていた場合、何が起きたのか分からない。

応募の後に求人が停止されることもある（ADR 0018）。
応募先がいまどうなっているかが分からないと、待ち続けることになる。

## 決定

- 取消は状態を `withdrawn` へ変えるだけとし、**行は消さない**
- 取り消せるのは `submitted` の応募だけとする
- 取り消した応募も一覧に残す
- **取り消した後も、同じ求人へは応募し直せない**
- 取消の前に、応募し直せないことを画面で伝える
- 一覧・詳細は応募時点の写しを出す。現在の求人の値は出さない
- 応募先の求人がいま公開中かどうかを、詳細に示す
- 取消の理由は記録しない
- 応募の一覧はプロフィールの下（`/:locale/profile/applications`）へ置く

## 理由

行を消さないのは、企業側から見て「応募がなかったこと」になるためである。
選考を始めていた相手が消えた場合、企業側は何が起きたのかを追えない。
状態として残せば、「応募があり、取り消された」ことが双方から見える。

`submitted` だけを取り消せるようにするのは、
取消を繰り返しても意味がなく、更新の時刻だけが動くためである。

再応募を許さないのは、ADR 0034 と同じ理由である。
同じ求人に同じ人の応募が複数並ぶと、企業側がどれを見ればよいか判断できない。
「取り消してから出し直す」を許すと、実質的に写しの差し替えになる。
応募時点の内容を固定した意味が失われる。

そのうえで、取消の前に必ず伝える。
知らずに取り消して応募できなくなるのは、取り返しがつかない。

一覧・詳細に写しを出すのは、現在の求人の値を出すと
題名が変わったときに「応募した覚えのない求人」が並ぶためである。

いまの公開状態を別に示すのは、写しだけでは
その求人がまだ募集しているかが分からないためである。
写し（応募時点）と現況（いま）は別のことであり、両方を出す。

取消の理由を記録しないのは、書かせても企業側が使える情報にならないためである。
理由を求めると、取り消しにくくする圧力にもなる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 取消で行を消す | 企業側から見て「応募がなかったこと」になり、何が起きたか追えない |
| 取り消した応募を一覧から隠す | 自分が取り消したことを確かめられない |
| 取消後の再応募を許す | 写しの差し替えになり、応募時点を固定した意味が失われる |
| 取消の前に伝えない | 知らずに取り消して応募できなくなる。取り返しがつかない |
| 一覧に現在の求人の値を出す | 題名が変わると「応募した覚えのない求人」が並ぶ |
| 現況を出さない | すでに募集が終わっている求人を待ち続ける |
| 取消の理由を必須にする | 取り消しにくくする圧力になる。企業側が使える情報にもならない |

## 影響

- 企業側から取消が見えるようにするのは P7-T3 で扱う
- 取消を企業へ知らせるかは P7-T4（通知）で決める
- 選考が進んだ後の取消の扱い（面接の予定など）は P8 で決める
- 応募し直したい場合の経路はない。
  必要になった場合は「取消の取消」ではなく、別の応募として設計し直す
- プロフィールを削除すると応募も消える（ADR 0034）。
  企業側に残す記録は応募イベント（P7-T4）が持つ
