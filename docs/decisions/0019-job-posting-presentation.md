# ADR 0019: 求人の公開時の見え方を 1 つの部分テンプレートへ置く

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0017 で公開申請と審査を作った。
審査する側は、求人の内容を編集フォームの入力欄としてしか見られない。
公開後にどう見えるかは、公開してからでないと確認できない。

P4 の対象範囲は「プレビュー」を含む。

公開側の表示（P5 Public Job Discovery and SEO）はまだ作っていない。
プレビューを先に作ると、公開時の見え方をここで定義することになる。

## 決定

- 公開時の見え方は、部分テンプレート `job_postings/_public` 1 つとする
- プレビューはその部分テンプレートを、通常のレイアウトの上へ描画する
- P5 の公開ページも同じ部分テンプレートを使う
- 未入力の項目は行ごと出さない
- 本文と応募条件は `simple_format` で改行を保つ
- プレビューであることを画面で明示し、そのときの状態も示す
- プレビューは `noindex, nofollow` を持つ
- `robots` の宣言は、必要な画面だけが `content_for :robots` で行う
- プレビューを見られるのは、その組織の所属者だけとする
- どの状態の求人でもプレビューできる

## 理由

見え方を 1 つの部分テンプレートへ置くのは、
プレビューと公開が食い違わないようにするためである。
2 か所へ書くと、片方を直したときにもう片方が古いままになる。
「プレビューでは問題なかったが公開すると違った」という状態は、
プレビューの目的そのものを失わせる。

未入力の項目を出さないのは、空欄を並べると
その項目が「無い」のか「書かれていない」のかが読み手に分からないためである。
応募者にとって「給与: （空欄）」は、給与が無いのか未記載なのかを判断できない。

改行を保つのは、書き手の段落をつぶさないためである。
求人の本文は箇条書きや段落で構成されることが多い。

プレビューであることを明示するのは、公開済みかどうかを見分けられなくなるためである。
状態も併せて示す。

`noindex, nofollow` を付けるのは、公開前の内容が検索から到達できると
公開の判断より先に外へ出るためである。

`robots` を必要な画面だけの宣言にするのは、既定を「検索結果へ載せる」にするためである。
既定を `noindex` にすると、公開ページを足すたびに解除の宣言が要り、
書き忘れが「公開したのに検索に出ない」形で現れる。
この向きの書き忘れは気付きにくい。

どの状態でもプレビューできるのは、審査の前に内容を確認する用途が中心だからである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| プレビューと公開で別のテンプレートを持つ | 片方が古いままになり、プレビューの目的を失う |
| 未入力の項目も空欄で出す | 「無い」のか「未記載」なのかが読み手に分からない |
| 本文の改行を無視する | 書き手の段落がつぶれる |
| プレビューであることを示さない | 公開済みかどうかを見分けられない |
| すべての画面を既定で `noindex` にする | 公開ページで解除を書き忘れると、検索に出ない状態に気付きにくい |
| 公開済みの求人だけプレビューできる | 審査の前に内容を確認する用途を満たせない |

## 影響

- P5 で公開ページを作るときは、この部分テンプレートを使う。
  公開ページ固有の要素（構造化データ、共有用の情報）は、その外側へ足す
- 求人の表示に使うスタイルは `application.css` へ置いた。
  静的エラー画面のインライン CSS とは同期しない（ADR 0003）
- 印刷用の表示、共有用の画像、構造化データはまだない
- プレビューの URL は組織の下にあり、所属者しか到達できない。
  外部の関係者へ見せる用途には使えない
