# ADR 0022: 給与を自由記述と構造化された値の両方で持つ

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

ADR 0016 で、求人の給与を自由記述（`salary`）とした。
「年収 500 万円〜700 万円」「経験に応じて相談」のように書けるが、
金額での絞り込みができない。

P4 の完了記録に
「給与と勤務地が文字列である。金額や地域での絞り込みはできない。
P5 の絞り込みで構造化の要否を判断する」と残した。

P5 の対象範囲は「給与絞り込み」を含む。
給与は求職者が最も使う条件のひとつである。

自由記述をやめて数値だけにすると、金額で表せない条件が書けなくなる。
「経験に応じて相談」「ストックオプション別途」のような表現は、
数値へ落とすと意味が変わる。

通貨は 1 つに固定できない。
自己ホスト可能な OSS として配布するため、どの国で使われるかを決められない。

## 決定

- 自由記述の `salary` は残す。詳細の表示にはこれも使う
- 構造化された `annual_salary_min` / `annual_salary_max`（整数）を足す
- 通貨は `salary_currency` として持ち、`JPY` / `USD` / `EUR` へ閉じる
- 3 つとも任意とする
- 下限だけ、上限だけの入力を許す
- 上限が下限を下回る入力を拒否する
- 金額を持つなら通貨も持つことを求める
- 負の金額を拒否する
- 公開側の絞り込みは「通貨」と「最低年収」の組で行う
- 通貨をまたいだ比較はしない
- 金額を持たない求人は、金額の条件を指定したときに結果へ含めない
- 換算、為替、時給・月給への対応は行わない

## 理由

自由記述を残すのは、金額で表せない条件があるためである。
構造化された値だけにすると、その求人は給与欄を空にするか、
実態と違う数値を入れることになる。

年収に限るのは、比較できる単位を 1 つに決めるためである。
時給と月給と年収が混ざると、絞り込みの結果が意味を持たない。
時給で募集する求人は、年収へ換算した値を入れるか、
構造化された値を持たずに自由記述だけを使う。

通貨を求人ごとに持つのは、1 つのインスタンスの中でも
複数の国の求人が並びうるためである。

通貨をまたいで比較しないのは、換算が為替の時点を決めないと成り立たないためである。
「いつの為替で換算したか」を持たない比較は、結果が日によって変わる。
利用者が通貨を選んでから金額を指定する形にすれば、この問題は起きない。

金額を持たない求人を条件から外すのは、
「未記載」を「条件を満たす」と扱うと結果が信用できなくなるためである。
逆に「未記載」を常に含めると、絞り込みの意味が薄れる。

上限と下限の順序、通貨の有無を検証するのは、
表示の時点でしか気付けない矛盾を、保存の時点で止めるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 自由記述をやめて数値だけにする | 金額で表せない条件が書けなくなる |
| 構造化せず自由記述のままにする | 求職者が最も使う条件で絞り込めない |
| 通貨を 1 つに固定する | 自己ホストでどの国で使われるかを決められない |
| 通貨を換算して比較する | 為替の時点を決めないと、結果が日によって変わる |
| 時給・月給も同じ列で持つ | 単位が混ざり、絞り込みの結果が意味を持たない |
| 金額を持たない求人も条件に含める | 絞り込みの意味が薄れる |
| 金額の検証をせず表示で吸収する | 表示の時点でしか矛盾に気付けない |

## 影響

- 求人の入力欄が 3 つ増える。いずれも任意である
- 詳細と一覧に「年収」の行が増える。金額を持たない求人では出ない
- 時給・月給で募集する求人は、年収へ換算した値を入れるか、
  構造化された値を持たずに自由記述だけを使う
- 給与の範囲による並び替えはない。結果は常に新しい順である
- 勤務地は文字列のままである。地域での絞り込みは部分一致に依存する。
  構造化の要否は別途判断する
