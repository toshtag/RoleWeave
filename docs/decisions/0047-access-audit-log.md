# ADR 0047: 個人情報を読んだ操作を記録し、運営者だけが見る

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P10 の完了条件は「個人情報に対する操作が監査ログに残る」を含む。

これまでに残してきたのは、**状態を変えた操作**の記録である。
所属の変更（ADR 0014）、公開状態（ADR 0018）、応募と選考（ADR 0037、0038）。

**読んだことは残っていなかった。**
企業の担当者が誰のプロフィールを開いたか、履歴書を取得したかは、どこにも残らない。
公開範囲（ADR 0030）で「見えること」は制御しているが、
実際に見られたかどうかは分からない。

情報が漏れた場合、誰が何を取得したかを追えないと、範囲を確かめられない。

## 決定

- 監査ログ（`access_events`）を追加する
- 記録するのは**個人情報を読んだ操作**とする
  - 企業側がプロフィールを開いた
  - 企業側が応募の詳細（応募時点の写し）を開いた
  - 企業側が添付を取得した
  - 本人が自分のデータをエクスポートした
- 誰が・いつ・何に対して・どこから（IP アドレス）を残す
- 対象の**表示名を写して持つ**。対象が消えても何に対する操作かが読める
- 記録は後から変えられない
- **見えなかった場合（404）は記録しない**
- 一覧は**運営者だけ**が見る
- 保持期限（ADR 0046）の対象へ加える（1 年、削除）

## 理由

読んだ操作を残すのは、見えることの制御だけでは足りないためである。
権限が正しくても、必要のない閲覧は起こりうる。
記録がなければ、後からそれを確かめる手段がない。

本人によるエクスポートも記録するのは、
持ち出しがあったこと自体を後から確かめる必要があるためである。
アカウントが乗っ取られた場合、最初に行われるのは持ち出しである。

表示名を写すのは、対象が消えた後でも読めるようにするためである
（応募の記録（ADR 0037）と同じ形にそろえた）。

404 で記録しないのは、読めていない操作を「読んだ」として残すと、
記録の意味が変わるためである。
一方、試みそのものを追いたい要求は別に存在しうる。必要になった時点で分けて足す。

運営者だけが見るのは、「誰が誰の情報を読んだか」がそれ自体、個人に関わる情報だからである。

**求職者へ「誰が見たか」を見せることは、この段階では行わない。**
見せると、応募者は「見られていない」ことからも意味を読み取る。
選考の状況の伝え方（ADR 0042）とあわせて決めるべきことであり、
記録を作ることとは別の判断である。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 読んだ操作を記録しない | 見えることの制御だけでは、実際の閲覧を確かめられない |
| 404 の試みも記録する | 読めていない操作が「読んだ」として残る |
| 求職者へ「誰が見たか」を見せる | 見られていないことからも意味を読み取る。別の判断が要る |
| 記録を誰でも見られるようにする | 誰が誰を見たかは、それ自体が個人に関わる情報である |
| 記録を変更・削除できるようにする | 変えられる記録は、監査の役に立たない |
| 一覧の操作（応募の一覧）も記録する | 件数が膨らむ。個別の閲覧が埋もれる |

## 影響

- 一覧の閲覧（応募の一覧、求人の一覧）は記録していない。
  個別の詳細を開いた時点で記録する
- 記録は 1 年で削除する（ADR 0046）。それより長い調査はできない
- 記録の改ざん検出（署名・チェーン）は行っていない。
  データベースへ直接触れる者は書き換えられる
- 外部への転送（SIEM）は行っていない
- 記録の失敗は握り潰さない。記録できなければ、その操作も失敗する
