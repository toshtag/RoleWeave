# ADR 0029: 希望条件を別の表に置き、完成度を割合で出さない

- 状態: 採用
- 決定日: 2026-08-02

この文書は日本語版を正本とする。

## 背景

P6 の対象範囲は「希望条件」と「プロフィール完成度」を含む。

希望条件は求人の側の項目と突き合わせて読まれる。
求人は `JobPosting::EMPLOYMENT_TYPES` と `JobPosting::SALARY_CURRENCIES` を持つ（ADR 0016、ADR 0022）。
語彙が食い違うと、突き合わせができない。

ADR 0026 では、職歴・学歴・スキル・希望条件を別のテーブルとして足すと記録した。
その理由として挙げたのは「1 つのプロフィールに複数の職歴が並ぶため」である。
希望条件は 1 つしか並ばない。理由が当てはまらない。

完成度は、埋まっていない項目を示すために要る。
一方で、割合や点数として出すと、数字を上げるために埋める動機が生まれる。
プロフィールは応募者の個人情報であり、埋めるほど良いものではない。

## 決定

- 希望条件（`desired_conditions`）はプロフィールへ **1 対 1** で従属する。
  プロフィールの列にはしない
- 雇用形態と通貨は `JobPosting` の定数をそのまま参照する。
  一致をテストで固定する
- 希望年収の下限は 0 以上の整数とする
- **通貨のない希望年収と、希望年収のない通貨をどちらも拒否する**
- すべて未入力の希望条件を保存できる
- 完成度（`ProfileCompleteness`）は保存せず、そのつど数える
- **割合・点数・進捗の棒として出さない。**そろっていない項目を名前で示す
- 中身のない希望条件は「そろっている」と数えない
- 作成と編集を分けず、1 つの編集画面から書く

## 理由

希望条件を別の表に置くのは、公開範囲がほかの項目と違うためである。
希望年収は、職歴や学歴と同じ扱いで企業へ渡してよい情報ではない。
プロフィールの列にすると、公開範囲を項目ごとに決めるときに
同じ行の中で分けることになる。表が分かれていれば、行ごとに決められる。

ADR 0026 が挙げた理由（複数並ぶため）は希望条件に当てはまらない。
別の理由（公開範囲が違う）で同じ結論に至ったため、決定は変えていない。

語彙を求人から参照するのは、写して持つと片方だけ増えた状態が生まれるためである。
求人へ「業務委託」を足して希望条件へ足し忘れると、
その働き方を希望として選べない。
定数の参照だけでは気付けないため、一致をテストで固定した。

通貨と金額を対で必須にするのは、通貨のない金額が読めないためである。
`5,000,000` が円なのかドルなのかで、意味は 100 倍以上違う。
逆に、金額のない通貨は何も示していない。

完成度を割合で出さないのは、数字が目標になるためである。
「80% です」と出せば、残りを埋める動機が生まれる。
そこで埋められるのは、応募に不要な個人情報かもしれない。
名前で示せば、何が足りないかは伝わり、埋めるかどうかは応募者が決められる。
画面には「書かずに応募することもできます」と明示する。

中身のない希望条件をそろったと数えないのは、
保存操作だけで数が動くと、確認の意味がなくなるためである。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| 希望条件をプロフィールの列にする | 公開範囲を項目ごとに決めるときに、同じ行の中で分けることになる |
| 語彙を希望条件へ写して持つ | 片方だけ増えた状態が生まれ、選べない選択肢ができる |
| 語彙の一致をテストで固定しない | 定数を写した変更が、静かに食い違いとして残る |
| 通貨なしの金額を許す | 金額の意味が通貨によって 100 倍以上変わる |
| 完成度を割合や点数で出す | 数字が目標になり、応募に不要な個人情報まで書かせる |
| 完成度を保存する | 更新のたびに数え直す場所が要る。数え漏れが古い値として残る |
| 希望条件の作成と編集を分ける | 利用者から見て同じ操作が 2 つの入口を持つ |

## 影響

- 希望条件と求人の突き合わせ（推薦・検索）は行っていない。
  語彙がそろっているため、必要になった時点で作れる
- 希望年収の上限は持たない。下限だけで足りるかは、応募の仕組みができてから判断する
- 完成度の項目（`ProfileCompleteness::ITEMS`）を増やすと、
  そろっていない項目として既存の利用者の画面にも現れる。
  増やす場合は、その項目が応募に本当に要るかを先に決める
- 希望条件は本人しか読み書きできない。企業側から見える経路は、
  公開範囲を決めるタスクで作る
