# ADR 0010: 認証の出来事を専用のテーブルへ記録する

- 状態: 採用
- 決定日: 2026-08-01

この文書は日本語版を正本とする。

## 背景

P2 の完了条件は「認証の成否が記録される」を含む。

記録がないと、次のいずれにも答えられない。

- 身に覚えのないログインがあったか
- 特定のアカウントへ繰り返し失敗した試行があったか
- パスワード再設定が完了したのはいつ、どこからか

記録は後から足すのが難しい。過去の出来事は復元できない。
一方で、記録する項目を後から減らすのも難しい。
すでに保存された値は、方針を変えても残り続ける。
そのため、何を記録し、何を記録しないかを最初に決める。

## 決定

- 認証の出来事は `authentication_events` テーブルへ 1 行ずつ記録する
- 記録する種類は次の 4 つとし、値を `AuthenticationEvent::KINDS` へ閉じる
  - `sign_in_succeeded` / `sign_in_failed` / `sign_out` / `password_reset_completed`
- 記録する項目は、種類・入力されたメールアドレス・アカウント・
  送信元 IP アドレス・User-Agent・時刻とする
- パスワード、token、セッションの識別子は記録しない
- メールアドレスは `User` と同じ規則で正規化して記録する
- `user_id` は任意とする。存在しないメールアドレスへの試行はアカウントへ結び付かない
- アカウントを削除しても記録は残す。外部キーは `on_delete: :nullify` とする
- 記録に失敗した場合、例外をそのまま呼び出し元へ返す
- 保存期間と削除処理は、この ADR では決めない

## 理由

専用のテーブルへ置くのは、アプリケーションのログとは寿命も用途も違うためである。
ログは運用のために短期間で回るが、認証の記録は
「いつからそのアカウントが使われていたか」を後から答えるために要る。

失敗を記録するのは、成功だけを残すと繰り返された試行が見えないためである。
繰り返しの検出は、試行回数の制限を設計するときの前提にもなる。

種類を値の一覧へ閉じるのは、自由な文字列を許すと
集計のたびに表記のゆれを吸収することになるためである。

メールアドレスを正規化するのは、`User` と規則がずれると
同じ相手の記録が表記ごとに分かれるためである。

`user_id` を任意にするのは、存在しないメールアドレスへの試行が
どのアカウントのものでもないためである。
ここでアカウントを必須にすると、最も見たい種類の失敗が記録できない。

アカウント削除で記録を残すのは、削除の前後の調査ができなくなるためである。
誰の操作だったかは `user_id` を空にすることで失われるが、
「いつ何が起きたか」は残る。

記録の失敗で例外を返すのは、「記録されているはず」と
「実際に記録されている」が食い違う状態を作らないためである。
記録を握りつぶすと、記録がないことが「起きなかった」を意味しなくなる。

## 記録しないもの

- パスワード（入力されたもの、保存されたもののいずれも）
- 確認・再設定の token
- セッションの識別子
- リクエストの本文、query string

入力されたメールアドレスは記録する。
ただし、利用者がパスワードをメールアドレスの欄へ入力した場合、
その値がこのテーブルへ残る。
この表は個人情報を含むものとして扱い、
参照できる範囲と保存期間は P10 Privacy, Security and Operations で決める。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| アプリケーションのログへ出すだけにする | 寿命と用途が違う。後から遡れる保証がない |
| 成功だけを記録する | 繰り返された試行が見えない |
| `user_id` を必須にする | 最も見たい種類の失敗（存在しないアドレスへの試行）を記録できない |
| アカウント削除で記録も消す | 削除の前後の調査ができなくなる |
| 記録の失敗を握りつぶす | 記録がないことが「起きなかった」を意味しなくなる |
| 入力されたメールアドレスを記録しない | 誰に対する試行かが分からず、繰り返しを検出できない |

## 影響

- 認証の経路ごとに、書き込みが 1 回増える
- `authentication_events` は個人情報（メールアドレス、IP アドレス、User-Agent）を含む。
  参照できる範囲、保存期間、削除処理は P10 で決める。
  現時点では無期限に残る
- 記録を利用者や管理者へ見せる画面はない。
  見せる範囲は、見せる相手が決まるタスク（P3 以降）で決める
- 試行回数の制限は入れていない。制限を入れるタスクは、この記録を前提にできる
