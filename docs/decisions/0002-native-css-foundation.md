# ADR 0002: 標準 CSS を画面スタイルの基盤とする

- 状態: 採用
- 決定日: 2026-07-31

この文書は日本語版を正本とする。

## 背景

P1-T1 で `/ja` と `/en` の入口 URL と、`main`、`h1`、`p` だけの最小 HTML が確定した。
一方、画面の見た目に関する基準はまだ存在しない。
色も余白も文字寸法も決まっていないため、現在の入口ページはブラウザーの既定表示のままである。

P1 では続けて共通レイアウト、ヘッダー、フッター、言語切替、エラー画面を作る。
これらはいずれも色、文字、余白、フォーカス表示を必要とする。
基準がないまま個別に作ると、同じ意味の値が画面ごとに別々の数値で散らばり、
後からまとめ直す作業が発生する。

そのため、部品を作る前に「何を使ってスタイルを書くか」と
「共通の値をどう置くか」を決めておく必要がある。
この判断は今後追加するすべての画面へ影響するため ADR として残す。

## 決定

- 画面のスタイルは、ブラウザーが直接解釈できる標準 CSS で書く
- Propshaft でその CSS をそのまま配信し、CSS のビルド工程を追加しない
- 共通の値は CSS Custom Properties でデザイン変数として定義する
- デザイン変数は `--blue-500` のような技術的な色名ではなく、
  `--color-link` のように用途を表す名前にする
- 生の色値はデザイン変数の宣言へ集約し、利用箇所では `var()` を使う
- 現在の規模では、デザイン変数と全体スタイルを `app/assets/stylesheets/application.css` の 1 ファイルに置く
- 実際の責務境界が生じるまで CSS ファイルを分割しない
- CSS framework、プリプロセッサ、CSS bundler を導入しない
- フォントは OS の system font を使い、外部 Web フォントを読み込まない
- UI 部品のスタイルは、それを必要とするタスクで追加する。
  未使用のスタイルやデザイン変数を先回りして作らない
- dark mode は必要性が確定した別のタスクで扱う

## 理由

Propshaft はブラウザーで解釈できるアセットをそのまま配信することを前提としており、
標準 CSS を置けば追加の変換なしに配信できる。
現在の画面数と CSS の量に対して、変換工程を持つことで得られるものがない。
一方で、ビルド基盤は導入した時点から更新と障害対応の対象になる。

CSS Custom Properties を使うのは、値の共有と可変値の表現が標準機能だけで済むためである。
プリプロセッサの変数と異なり、実行時に解決されるため、
将来 `@media` などの条件で値を切り替える必要が生じても仕組みを増やさずに済む。

デザイン変数を用途で命名するのは、色や寸法を変更したときに名前が嘘にならないようにするためである。
`--blue-500` はその値が青であることに依存しており、配色を見直すと名前と実体がずれる。
`--color-link` であれば、値を変えても意味は変わらない。

1 ファイルに置くのは、現時点で分割の基準が実在しないためである。
責務が確定していない段階で分割すると、どのファイルへ書くかの判断が
そのつど恣意的になり、結果として同じ種類のスタイルが複数のファイルへ散る。

system font を使うのは、外部 Web フォントが外部通信、読み込み遅延、
配信元への運用依存を持ち込むためである。
現時点でブランドとしての書体を決めていない以上、それらを負う理由がない。

未使用のスタイルを先回りして作らないのは、
使われていないスタイルは正しさを確認する手段がないためである。
実際の画面から参照されて初めて、その値が妥当かどうかを判断できる。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| Tailwind CSS | 現時点の画面数に対し、ビルド環境と依存関係が増える |
| Bootstrap | 未使用部品を含む包括的な UI 契約を早期に導入することになる |
| Sass | 現在必要な変数と可変値は標準 CSS で表現できる |
| PostCSS | 現段階では変換処理が必要な仕様がない |
| 外部 Web フォント | 外部通信、読み込み遅延、運用依存が増える |
| CSS ファイルの先行分割 | 実在しない責務境界を先に作ることになる |

## 影響

- 画面を追加するときは、色と余白を新たに決めず、既存のデザイン変数を参照する
- 新しいデザイン変数は、それを利用するスタイルと同じタスクで追加する
- CSS は追加の変換なしに配信されるため、書いた内容がそのままブラウザーへ届く。
  対応するブラウザーで解釈できる記法だけを使う
- コントラストなどの可読性は、変数の値を変更した時点で確認し直す必要がある

この ADR は「今後 CSS のツールを導入しない」と定めるものではない。
画面数、スタイルの量、重複の実測が、標準 CSS だけでは扱いにくい水準に達した場合は、
その実測を根拠として別の ADR で判断を差し替える。
dark mode、ブランドとしての配色と書体、UI 部品の標準形も、
それぞれ必要になったタスクで別途決定する。
