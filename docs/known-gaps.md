## authorization

| --- | --- |
| 組織のデータ | ADR 0013。`OrganizationScope` が常に所属から引く |
| 求人の公開の操作 | ADR 0017。申請は所属者、承認は管理者 |
| 選考の確定 | ADR 0038。面接へ進めるのは所属者、採否は管理者 |
| 求職者のプロフィール | ADR 0030、ADR 0036。判定は `CandidateProfile.visible_to` の 1 か所 |
| 添付 | ADR 0031。公開範囲と添付の設定の両方が要る |
| 会話 | ADR 0041。参加者は応募が決める |
| 運営者の経路 | ADR 0015。`Operator::BaseController` が 404 で隠す |
| 候補者検索の対象 | ADR 0055。判定は `CandidateProfile.searchable` の 1 か所。探せるのは組織の所属者だけ |
| タレントプールの表示 | ADR 0055。入れた時点ではなく、**いまの許可**で表示と件数を決める |
| スカウトの送信先 | ADR 0056。`searchable` と配信停止の両方を通ったときだけ送れる |
| Webhook の管理 | ADR 0057。**管理者だけ**が登録・削除できる |
| CSV の入出力 | ADR 0058。**管理者だけ**が扱える |

テスト: `organization_authorization_test`、`organization_isolation_test`、
`access_control_test`、`profile_visibility_test`、`selection_stage_test`、
`conversation_test`、`operator_test`、`candidate_search_test`、`scouting_test`、
`webhook_test`、`csv_integration_test`、`saved_search_test`

**権限がない場合は 404 とし、403 と分けない。**存在の有無を漏らさないためである。

## tenant_isolation

| 対象 | 根拠 |
| --- | --- |
| 組織へ従属するモデルの網羅 | `organization_scoping_test`（構造テスト） |
| 他組織の求人・応募・評価・予定 | 各機能のテストに「他組織から 404」を含む |

構造テストは `ApplicationRecord.descendants` を走査し、
組織を持つモデルが「必須」と「削除時に消える」を満たすことを確かめる。
除外は 3 件（`MembershipEvent`、`JobPostingEvent`、`AccessEvent`）で、
いずれも理由をコードへ書いている。

**走査であるため、後から足したモデルも自動で対象になる。**
P13・P14 で増えた `TalentPool`、`Scout`、`ScoutTemplate`、`ScoutBlock`、
`Webhook`、`IntegrationRun` も、一覧へ書き足すことなく同じ検証を受けている。

対象は `belongs_to :organization` を持つモデルである。
`TalentPoolMember` と `WebhookDelivery` は組織を直接持たず、
親（`TalentPool`、`Webhook`）を通して従属する。
**この 2 つは構造テストの対象に入らない。**分離は親の側で保証している。

## privacy

| 要件 | 根拠 |
| --- | --- |
| 収集目的 | 各 ADR の「背景」。持たない項目も明示（ADR 0026 の生年月日・性別・顔写真） |
| 公開範囲 | ADR 0030。**既定は `closed`** |
| 保持 | ADR 0046。表ごとに期間と消し方。網羅をテストで固定 |
| 削除・匿名化 | ADR 0033（本人による削除）、ADR 0046（期限） |
| 持ち出し | ADR 0032。出す列と出さない列の網羅をテストで固定 |
| 読んだ操作の記録 | ADR 0047。**候補者を検索したこと自体も残す**（ADR 0055） |
| 探されることの同意 | ADR 0055。`scout_opt_in` を別に持つ。**既定は false** |
| 外部へ送る内容 | ADR 0057。Webhook の本文は識別子・種類・時刻だけとし、個人情報を含めない |

**非公開を初期値とする**は、公開範囲・添付の公開・希望年収の公開・
受信の許可（`scout_opt_in`）・メールの受け取り（これは既定で有効）で守っている。
メールの受け取りだけを既定で有効にしているのは、
通知が届かないと選考が止まるためである（ADR 0042）。

「見せる」と「探される」を別の同意として扱う（ADR 0030、ADR 0055）。
公開範囲が `closed` の場合は、受信を許可していても検索の対象にしない。
**2 つの設定が食い違ったときは、閉じている側を優先する。**

**外部へ送った後は、こちらの設定が効かない。**
Webhook の送信先は利用者が決めるものであり、公開範囲（ADR 0030）も
保持期限（ADR 0046）も届かない。個人情報を本文へ入れないことで避けている。

## verification

| 要件 | 根拠 |
| --- | --- |
| 正の検証 | すべてのタスクの PR に `bin/verify` の結果を記載 |
| 負の検証 | すべてのタスクの PR に変異と結果を記載 |
| 完全検証 | すべてのタスクの PR に `bin/verify --full` の結果を記載 |

負の検証では、P10 の時点までに**検出できなかった変異が 10 件**あった。
いずれもテストを足して落ちるようにしている。
そのうち 3 件は同じ形（**値を定数から読むテストは、その定数の変更を検出しない**）だった。

P11 以降も同じ手順を続けている。件数はここでは追わない。
数えた根拠は各 PR にあり、**この文書へ写すと二重管理になって古くなる**。

### テストが緑でも守られていなかった例

依存の棚卸し（#216）で、**production の不具合が 1 件**見つかった。

`app/jobs/webhook_delivery_job.rb` が `Net::HTTP` を使いながら
`require "net/http"` を書いておらず、
test group の gem（capybara、selenium-webdriver）が
巻き添えで読み込んでいた。test group は production では読まれない。
production では最初の Webhook 配信で `NameError` になる状態だった。

**テストが緑だったのは、テスト用の gem が実装の欠落を隠していたからである。**
負の検証は「実装を壊してテストが落ちるか」を見るが、
このときテストは実装ではなく**実行環境**に守られていた。
壊す対象を実装に限ると、この形は見つからない。

見つかったのは、使っていない依存を外したときである。
依存を減らす作業には、実行環境が隠していたものを表に出す働きがある。
