# 企業の担当者として使う

この文書は日本語版を正本とする。

デモデータを入れた状態を前提とする。
`owner@example.invalid`（管理者）と `member@example.invalid`（一般の所属者）で、
できることの違いを試せる。

## 役割の違い

| 操作 | 管理者 | 一般の所属者 |
| --- | --- | --- |
| 求人を作る・編集する | できる | できる |
| 求人の公開を申請する | できる | できる |
| **求人を承認・差し戻し・停止する** | できる | **できない** |
| 応募を見る | できる | できる |
| 面接へ進める | できる | できる |
| **内定・採用・不採用・辞退を確定する** | できる | **できない** |
| 評価を書く | できる | できる |
| 担当者を決める | できる | できる |
| 人を招待する・役割を変える | できる | **できない** |
| 候補者を探す・タレントプールを使う | できる | できる |
| スカウトを送る | できる | できる |
| **外部への配信（Webhook）を登録する** | できる | **できない** |
| **求人の CSV を取り込む・書き出す** | できる | **できない** |

できない操作は、画面に出ないだけでなく**経路そのものが 404 を返す**。
権限がないことと、存在しないことを分けない
（[ADR 0013](../decisions/0013-role-based-authorization.md)）。

## 1. 組織を作る・人を集める

| やりたいこと | 経路 |
| --- | --- |
| 組織を作る | `/ja/organizations/new` |
| 所属する組織を見る | `/ja/organizations` |
| 所属者と履歴を見る | `/ja/organizations/:id/memberships` |
| 人を招待する | 所属者の画面から「招待する」 |

組織を作った人が最初の管理者になる。
**組織の最後の管理者は、役割を変えられない**（誰も操作できない組織を作らないため）。

## 2. 求人を出す

| やりたいこと | 経路 |
| --- | --- |
| 求人の一覧を見る | `/ja/organizations/:id/job_postings` |
| 求人を作る | `/ja/organizations/:id/job_postings/new` |
| 公開時の表示を確認する | 求人の一覧から「公開時の表示を見る」 |

求人は次の順に進む（[ADR 0017](../decisions/0017-job-posting-review.md)）。

```
下書き → 申請中 → 公開中 → 停止中 → 申請中 …
              ↘ 差し戻し → 申請中
```

**申請は誰でもできる。承認は管理者だけができる。**
公開中の求人は編集できない。直すには差し戻すか停止する。

## 3. 応募を見る

| やりたいこと | 経路 |
| --- | --- |
| 届いた応募を見る | `/ja/organizations/:id/job_postings/:job_posting_id/applications` |
| 応募の詳細を見る | 応募の一覧から応募者の名前 |
| 応募者の現在のプロフィールを見る | 応募の詳細から（公開範囲が許すときだけ） |

**見えるのは応募時点の写しである。**
応募者が後からプロフィールを変えても、この内容は変わらない。

応募の一覧を開いたこと、プロフィールを開いたこと、添付を取得したことは、
すべて記録に残る（[ADR 0047](../decisions/0047-access-audit-log.md)）。

## 4. 選考を進める

| やりたいこと | 経路 |
| --- | --- |
| 選考の段階を進める | 応募の詳細のボタン |
| 評価とコメントを書く | 応募の詳細の「社内の評価」 |
| 担当者を決める | 応募の詳細の「担当者」 |
| 面接の予定を入れる | 応募の詳細の「面接の予定」 |
| 結論の期限を決める | 応募の詳細の「結論を出す期限」 |

段階は `書類選考 → 面接 → 内定 → 採用` と進む。
不採用・辞退はどの段階からでも記録できる（[ADR 0038](../decisions/0038-selection-stage.md)）。

**採用・不採用・辞退は取り消せない。**確定した後は動かせない。

評価・面接の予定・期限は**応募者には見えない**。
面接の予定を入れても応募者へは伝わらない。日程はやり取りで伝える。

## 5. 応募者と連絡する

| やりたいこと | 経路 |
| --- | --- |
| やり取りを見る・送る | 応募の詳細から「やり取りを見る」 |

会話は応募ごとにある。応募を経由しない連絡はできない
（[ADR 0041](../decisions/0041-application-conversation.md)）。

応募が取り消されると、新しいメッセージは送れない。読むことはできる。

## 6. 候補者を探す・スカウトする

| やりたいこと | 経路 |
| --- | --- |
| 候補者を探す | `/ja/organizations/:id/candidate_searches` |
| プロフィールを見る | 検索の結果から「プロフィールを見る」 |
| タレントプールを作る・見る | `/ja/organizations/:id/talent_pools` |
| プールへ入れる | 検索の結果から「（プールの名前）へ追加」 |
| スカウトを送る | 検索の結果から「スカウトを送る」 |
| 送ったスカウトを見る | `/ja/organizations/:id/scouts` |
| テンプレートを管理する | `/ja/organizations/:id/scout_templates` |

**出るのは、スカウトの受信を許可した候補者だけである。**
許可していない候補者は、この画面に存在しない。
探せることと、応募者として見えることは別の判定である
（[ADR 0055](../decisions/0055-candidate-search.md)）。

結果に出るのは**限られた項目**（表示名・所在地・希望職種・スキル）だけである。
経歴の中身と添付は、応募か公開範囲の設定が許すときにだけ見える。

**候補者を検索したことは記録に残る**
（[ADR 0047](../decisions/0047-access-audit-log.md)）。

タレントプールは**組織の中で共有される**。
表示と件数は、**いまの時点で探せる候補者だけ**を数える。
入れた後に候補者が許可を取り消せば、プールからも消える。

スカウトには制限がある。

| 制限 | 内容 |
| --- | --- |
| 同じ候補者へ | **1 通だけ。**2 通目は送れない |
| 1 日あたり | **組織ごとに 50 通** |
| 配信停止 | 候補者が止めた組織からは送れない |
| 取り消し | **できない。**送った内容は後から変えられない |

**返信は届かない。**スカウトは一方向であり、続きは応募を経由する
（[ADR 0056](../decisions/0056-scouting.md)）。

## 7. 外部と連携する

**管理者だけが扱える。**

| やりたいこと | 経路 |
| --- | --- |
| 外部への配信（Webhook）を登録する | `/ja/organizations/:id/webhooks` |
| 求人の CSV を取り込む | `/ja/organizations/:id/job_posting_imports/new` |
| 求人の CSV を書き出す | 取り込みの画面から「現在の求人を CSV で書き出す」 |
| 実行の履歴を見る | 取り込みの画面の「実行の履歴」 |

Webhook で送るのは**識別子と種類と時刻だけ**である。個人情報は含まない。
送り先はこちらの管理下にないため、送った後は公開範囲も保持期限も効かない
（[ADR 0057](../decisions/0057-webhooks.md)）。

署名の秘密は**登録したときにしか画面に出ない**。その場で控える。

送信先は http/https に限られ、**内部のネットワークへは向けられない**
（[ADR 0060](../decisions/0060-webhook-destination-restriction.md)）。

CSV は `external_key` で照合する。あれば更新、なければ作成する。
**取り込んだ求人は必ず下書きになる。**公開には、いつもの申請と承認が要る。
1 行の失敗で全体は止まらない。失敗した行は履歴に残る
（[ADR 0058](../decisions/0058-csv-integration.md)）。

**候補者・応募者の CSV はない。**持たないことを決めている。
