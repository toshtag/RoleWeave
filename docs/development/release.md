# リリース手順

この文書は日本語版を正本とする。
版の付け方の判断は [ADR 0053](../decisions/0053-versioning-and-release.md) にある。

## 版の付け方

[Semantic Versioning](https://semver.org/lang/ja/) に従う。

`0.x` の間は、**次の版で互換性のない変更が入りうる**。
`1.0.0` は、自己ホストの利用者が本番で使える状態になってから付ける。

| 変更 | 上げる場所 |
| --- | --- |
| 互換性のない変更（データの移行が要る、経路が変わる） | `0.x.0` → `0.(x+1).0` |
| 機能の追加 | `0.x.0` → `0.(x+1).0` |
| 不具合の修正だけ | `0.x.y` → `0.x.(y+1)` |

`0.x` では、機能の追加と互換性のない変更を同じ位置で上げる。
`1.0.0` 以降は分ける。

## 出す前に確かめること

すべて通ってから進む。1 つでも落ちたら出さない。

```bash
docker compose run --rm app bin/verify
```

```bash
bin/verify --full
```

| 確認 | 方法 |
| --- | --- |
| 検証が通る | 上の 2 つが exit 0 |
| 移行が適用できる | `bin/verify --full` が Docker を作り直して確かめる |
| デモが入る | `bin/rails roleweave:demo:seed` が成功する |
| 変更の履歴が最新 | `CHANGELOG.md` にこの版の節がある |
| 既知の制限が最新 | `docs/quality/verification-status.md` を見直した |
| 依存に脆弱性がない | `bin/verify` の bundler-audit が通る |

## 手順

1. `CHANGELOG.md` へ版の節を書く（入っているもの・入っていないもの・既知の制限）
2. `main` へマージする
3. 注釈付きのタグを作る

```bash
git tag -a v0.1.0 -m "v0.1.0"
git push origin v0.1.0
```

4. GitHub の Release を作る（任意）
   - タグを選び、`CHANGELOG.md` の該当の節を本文へ貼る
   - **維持している人が行う。**自動では公開しない

## 出さないもの

- コンテナイメージ（配るのはソースと手順である）
- 常設の公開環境（P12 の非目標）
- 商用サポート

## 版を戻すとき

タグは消さない。消すと、その版を取得していた人の参照が壊れる。
問題が見つかった場合は、**次の版を出して直す**。

`CHANGELOG.md` には、その版に問題があったことを残す。
履歴から消すと、同じ問題を踏んだ人が原因にたどり着けない。
