# 開発言語・命名ポリシー

どこで日本語を使い、どこで英語を使うかを決める。
開発者と AI Agent が同じ判断基準で作業できるようにするためである。

この文書は日本語版を正本とする。

## 1. 使い分け

- 人間が読んで議論するための文章は日本語で書く
- 機械が解釈する識別子は英語で書く
- 利用者に表示される文字列は日本語と英語の両方を提供する

| 日本語 | 英語 |
| --- | --- |
| コードコメント、テストの説明 | クラス名、モジュール名、メソッド名、変数名 |
| コミット本文、PR タイトルの要約、PR 本文 | ファイル名、ディレクトリ名 |
| Issue、タスク定義、レビュー記録、検証結果 | データベース名、テーブル名、カラム名 |
| ADR および設計文書の本文 | URL、API フィールド、i18n キー |
| 開発者向けの主要ドキュメント | 構造化ログのキー、内部イベント名 |
| — | Git ブランチ名、Conventional Commits の種別 |

## 2. コメント

コメントは、処理内容を日本語で言い換えるために書かない。
コードを読めば分かることを繰り返すコメントは、保守されずに嘘になる。

書くのは次を説明する必要がある場合に限る。

- なぜその設計を選んだのか
- どのような制約があるのか
- どこに注意しなければ壊れるのか
- 一見不自然に見える実装が、なぜ必要なのか

書かない例

```ruby
# 求人を取得する
job_posting = JobPosting.find(params[:id])
```

書く例

```ruby
# 応募時点の条件を証跡として残すため、公開中の求人でも本文をコピーして保持する。
# 求人が後から編集されても、応募内容の意味が変わらないようにする。
snapshot = job_posting.attributes.slice(*SNAPSHOT_COLUMNS)
```

## 3. テストの説明

テストが何を保証しているのかを日本語で書く。
実装の呼び出し手順ではなく、期待する振る舞いを書く。

```ruby
test "メールアドレスが重複するアカウントを保存できない" do
```

## 4. コミットメッセージ

種別は英語、要約と本文は日本語とする。

```text
feat: 求人の下書き作成を追加
fix: 非公開求人へのアクセスを拒否
docs: 開発言語ポリシーを明文化
```

| 種別 | 用途 |
| --- | --- |
| `feat` | 利用者から見た機能の追加 |
| `fix` | 不具合の修正 |
| `refactor` | 振る舞いを変えない内部改善 |
| `test` | テストの追加・修正 |
| `docs` | ドキュメントの追加・修正 |
| `chore` | ビルド、依存関係、開発環境 |
| `ci` | CI 設定 |
| `perf` | 性能改善 |

PR タイトルも同じ形式とする。本文の構成は
[`../../.github/pull_request_template.md`](../../.github/pull_request_template.md) に従う。

## 5. ブランチ名

小文字 ASCII 英数字とハイフンを使い、区切りのスラッシュを 1 つ持つ。
大文字、アンダースコア、日本語、2 つ以上のスラッシュは使わない。

```regex
^[a-z0-9]+/[a-z0-9]+(?:-[a-z0-9]+)*$
```

```text
docs/backup-procedure-and-verification-status
deps/drop-unused-gems
p0/r9-db-data-volume-name
```

## 6. 利用者向け表示

- すべての利用者向け文字列は i18n を経由する
- 日本語と英語を同じ変更で実装する。
  葉キーの一致はテスト（`i18n_configuration_test`）で固定している
- i18n キーは英語で、意味の階層を持たせて命名する

```yaml
job_postings:
  show:
    apply_button: 応募する
```

## 7. 文書の言語

`README.md` は日本語、`README.en.md` は英語とし、相互にリンクする。
設計上の正本は日本語版とする。

| 範囲 | 扱い |
| --- | --- |
| 利用者向け UI、公開仕様、セットアップ手順、操作文書 | 日本語と英語の両方を提供する |
| 内部設計文書、ADR、タスク定義、レビュー記録、検証結果 | 日本語を正本とし、英訳を必須としない |

英訳を必須としない範囲であっても、
**英語版だけに存在する約束を作らない。**

## 8. 名前の付け方

- 過去のシステムに由来する固有名詞を使わない
- 意味が通じない造語を作らない
- 日本語を機械的に直訳した不自然な英語を使わない
- 実在する人物、会社、求人情報をデモデータに使わない
- 内部の業務用語には、採用領域で広く通用する英語を使う。
  独自の言い換えを増やさない

## 9. `RoleWeave` の使用範囲

`RoleWeave` は **Rails アプリケーション設定の名前空間に限定する。**
業務モデルと業務モジュールは、トップレベルの自然な英語名とする。

| 許容 | 禁止 |
| --- | --- |
| `RoleWeave::Application` | `RoleWeave::JobApplication` |
| `JobPosting`、`JobApplication`、`CandidateProfile` | `RoleWeaveJobApplication` |
| `app/models/job_application.rb` | `app/models/role_weave/job_application.rb` |
| — | `role_weave_job_postings`（テーブル名） |

業務定数を `RoleWeave` の配下へ置くと、ブランド名を含む物理パスか、
独自の autoload 設定が必要になる。
どちらも「Rails 標準から外れない」（[`../principles.md`](../principles.md)）と両立しない。

`RoleWeave::Application` は Rails の設定クラスであり、応募を表す業務モデルではない。
応募は `JobApplication` とし、`ApplicationRecord` と `ApplicationController` との
意味上の混同を避ける。

`RoleWeave` 以外のブランド名を新しく作らない。
