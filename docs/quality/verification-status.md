# 横断品質要件の検証状況

この文書は日本語版を正本とする。
対象は P0 から P10-T4 までにマージされたもの（PR #145 まで）。

`docs/quality/cross-cutting-requirements.md` の各要件について、
どこで満たしているかと、満たしていない点を書く。
**満たしていない点を隠さない。**書かないと、次に読む人は満たされていると読む。

## authorization

| 対象 | 根拠 |
| --- | --- |
| 組織のデータ | ADR 0013。`OrganizationScope` が常に所属から引く |
| 求人の公開の操作 | ADR 0017。申請は所属者、承認は管理者 |
| 選考の確定 | ADR 0038。面接へ進めるのは所属者、採否は管理者 |
| 求職者のプロフィール | ADR 0030、ADR 0036。判定は `CandidateProfile.visible_to` の 1 か所 |
| 添付 | ADR 0031。公開範囲と添付の設定の両方が要る |
| 会話 | ADR 0041。参加者は応募が決める |
| 運営者の経路 | ADR 0015。`Operator::BaseController` が 404 で隠す |

テスト: `organization_authorization_test`、`organization_isolation_test`、
`access_control_test`、`profile_visibility_test`、`selection_stage_test`、
`conversation_test`、`operator_test`

**権限がない場合は 404 とし、403 と分けない。**存在の有無を漏らさないためである。

## tenant_isolation

| 対象 | 根拠 |
| --- | --- |
| 組織へ従属するモデルの網羅 | `organization_scoping_test`（構造テスト） |
| 他組織の求人・応募・評価・予定 | 各機能のテストに「他組織から 404」を含む |

構造テストは `ApplicationRecord.descendants` を走査し、
組織を持つモデルが「必須」と「削除時に消える」を満たすことを確かめる。
除外は 3 件（`MembershipEvent`、`JobPostingEvent`、`AccessEvent`）で、
いずれも理由をコードへ書いている。

## privacy

| 要件 | 根拠 |
| --- | --- |
| 収集目的 | 各 ADR の「背景」。持たない項目も明示（ADR 0026 の生年月日・性別・顔写真） |
| 公開範囲 | ADR 0030。**既定は `closed`** |
| 保持 | ADR 0046。表ごとに期間と消し方。網羅をテストで固定 |
| 削除・匿名化 | ADR 0033（本人による削除）、ADR 0046（期限） |
| 持ち出し | ADR 0032。出す列と出さない列の網羅をテストで固定 |
| 読んだ操作の記録 | ADR 0047 |

**非公開を初期値とする**は、公開範囲・添付の公開・希望年収の公開・
メールの受け取り（これは既定で有効）で守っている。
メールの受け取りだけを既定で有効にしているのは、
通知が届かないと選考が止まるためである（ADR 0042）。

## localization

| 要件 | 根拠 |
| --- | --- |
| 日英の同時実装 | `i18n_configuration_test` が**葉キーの一致**と**重複キーの不在**を確かめる |
| 画面の言語 | 各機能のテストに「日本語と英語で表示する」を含む |
| メールの言語 | 送信の locale を明示（ADR 0001 の契約をメールでも維持） |
| フォールバック | `config.i18n.fallbacks = false`。訳の欠落は test で例外になる |

## accessibility

| 要件 | 根拠 |
| --- | --- |
| 画面の骨格（main / h1 / lang / viewport / スキップリンク / tabindex） | `shared_page_contract_test` |
| 項目の誤りの結び付け | `field_error_id` と `aria-describedby`（登録・プロフィール・職歴ほか） |
| 静的エラー画面 | `error_pages_test`、`shared_page_contract_test` |

**このタスクで是正した点**:
`shared_page_contract_test` は未ログインで到達できる画面しか見ていなかった。
P4 以降に増えた画面（プロフィール、職歴、応募、通知、組織、求人）は
1 つも共通契約の検証を受けていなかった。
ログインを要する 17 画面を対象へ加えた。

**満たしていない点**:

- 色のコントラスト比を検証していない。目視でも自動でも確かめていない
- 支援技術での実操作を確かめていない
- 動的な更新（Turbo の差し替え）の読み上げを確かめていない

## verification

| 要件 | 根拠 |
| --- | --- |
| 正の検証 | すべてのタスクの PR に `bin/verify` の結果を記載 |
| 負の検証 | すべてのタスクの PR に変異と結果を記載 |
| 完全検証 | すべてのタスクの PR に `bin/verify --full` の結果を記載 |

負の検証では、これまでに**検出できなかった変異が 10 件**あった。
いずれもテストを足して落ちるようにしている。
そのうち 3 件は同じ形（**値を定数から読むテストは、その定数の変更を検出しない**）だった。

## 全体として満たしていない点

| 点 | 扱い |
| --- | --- |
| 色のコントラスト比の検証 | 未実施。P11 以降で扱うかを判断する |
| 支援技術での実操作 | 未実施。自動検証では代えられない |
| メッセージの添付 | 未実装（P9 の対象範囲だが完了条件外） |
| 運営者による操作の一部（権限の付与）の記録 | rake タスクからの実行であり、記録に残らない |
| 記録の改ざん検出 | なし（ADR 0047） |
| 侵入テスト・第三者監査 | 非目標 |
