# 脅威モデル

この文書は日本語版を正本とする。

何から守っているのかを書く。書かないと、人によって前提が変わる。
対策そのものは各 ADR が持つ。ここは全体の見取り図である。

## 守る対象

優先度の高い順に挙げる。

1. **求職者の個人情報** — プロフィール、職歴、学歴、スキル、希望条件、履歴書、応募の内容
2. **選考の情報** — 評価、面接の予定、応募の状況。漏れると求職者と企業の双方が不利益を受ける
3. **アカウントの制御** — ログイン、パスワード、セッション
4. **組織のデータ** — 求人、所属、権限
5. **サービスの継続** — 応募や連絡ができる状態

## 想定する攻撃者

| 攻撃者 | 動機 | 前提の権限 |
| --- | --- | --- |
| 外部の第三者 | 個人情報の収集、乗っ取り | なし |
| 登録した利用者 | 他人の情報の閲覧 | 自分のアカウント |
| 組織の所属者 | 他組織の情報、権限の逸脱 | 所属する組織の中の権限 |
| 求人を装う組織 | 応募者の個人情報の収集 | 組織を作れる |
| 運営者（サーバーの管理者） | — | すべて |

**運営者は攻撃者として扱わない。**自己ホストの前提では、
運営者はサーバーとデータベースへ直接触れられる。
アプリケーション側で防ぐことはできない。
できるのは「運営者が行った操作を記録に残す」ことである（ADR 0015、ADR 0047）。

## 信頼境界

- ブラウザーとアプリケーションの間（HTTPS、CSP、CSRF、セッション）
- アプリケーションとデータベースの間（同じ運用者の管理下）
- アプリケーションと SMTP の間（外部へ出る。中身を書かない）
- アプリケーションとファイルの保存先（同じ運用者の管理下）

## 脅威と対策

| 脅威 | 対策 | 正本 |
| --- | --- | --- |
| 他人のアカウントへの乗っ取り（総当たり） | bcrypt、最小 12 文字、レート制限 | ADR 0006、ADR 0044 |
| セッションの盗用 | DB のセッション、httponly、SameSite=Lax、署名付き Cookie | ADR 0007 |
| メールアドレスの詐称 | 確認メール。未確認では主要な操作を行えない | ADR 0008 |
| 再設定リンクの悪用 | 短い有効期限、パスワードの変更で無効化 | ADR 0009 |
| 他組織のデータの参照 | 対象を常に所属から引く。404 で存在も隠す | ADR 0013 |
| 権限の逸脱（承認・確定） | 管理者だけの操作を分ける | ADR 0017、ADR 0038 |
| 求職者の情報の無断閲覧 | 既定で非公開。判定は 1 か所 | ADR 0030、ADR 0036 |
| 履歴書の流出 | 公開範囲と別の設定、自前の経路から配信、`attachment` で返す | ADR 0031 |
| 悪意のある添付 | PDF だけ、大きさの上限、`Content-Disposition: attachment` | ADR 0031 |
| CSRF | Rails の既定の保護。テストで固定 | ADR 0045 |
| XSS | CSP（`script-src 'self'`、nonce なし）、ERB の自動エスケープ | ADR 0045 |
| クリックジャッキング | `frame-ancestors 'none'` | ADR 0045 |
| メール経由の情報の漏えい | 本文に中身を書かない | ADR 0037、ADR 0042 |
| 個人情報の無期限の保持 | 保持期限と匿名化 | ADR 0046、ADR 0033 |
| 誰が読んだか分からない | 読んだ操作の記録 | ADR 0047 |
| 大量送信・大量作成 | レート制限 | ADR 0044 |
| 外部への配信を使った内部ネットワークへの到達（SSRF） | 解決した IP を判定し、その IP へ接続する。失敗は種別だけ残す | ADR 0060 |
| 書き出した CSV を開いた端末での数式の実行 | 数式になる値へ文字列の印を付ける | ADR 0061 |
| 依存の脆弱性 | `bundler-audit` を検証へ組み込む | `bin/verify` |
| 静的解析で分かる欠陥 | `brakeman` を検証へ組み込む | `bin/verify` |

## 受け入れているリスク

対策していない。理由とともに残す。

| リスク | 理由 |
| --- | --- |
| 運営者による閲覧・改ざん | 自己ホストの前提。アプリケーション側で防げない |
| 監査ログの改ざん | データベースへ直接触れる者は書き換えられる（ADR 0047） |
| ウイルスを含む添付 | 検査の仕組みを持たない。PDF に限定し、常に添付として返す（ADR 0031） |
| 自動化された試行（CAPTCHA なし） | レート制限までとする（ADR 0044） |
| 同じ IP を共有する利用者への巻き添え | レート制限の副作用（ADR 0044） |
| メールの盗み見 | 経路の安全は SMTP の設定に依存する。本文に中身を書かないことで影響を抑える |
| 求人を装う組織による情報収集 | 組織の実在の確認を行っていない。公開範囲を既定で閉じることで影響を抑える |
| 応募内容の写しの保持 | 応募時点の内容は取消後も企業側に残る（ADR 0035、ADR 0036） |
| バックアップからの復元による「消したはずのデータ」の復活 | 運用の手順に依存する（`docs/development/backup-and-restore.md`） |
| 明示して許した内部の配信先の悪用 | `WEBHOOK_ALLOWED_HOSTS` は運営者が書く設定である。既定は拒否とする（ADR 0060） |

## この文書の更新

新しいフェーズで個人情報や権限に関わるものを足したときは、
その ADR とあわせてこの表へ行を足す。
「対策していない」ことも、行として残す。
