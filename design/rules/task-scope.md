# タスクスコープルール

- タスクに宣言された write scope 以外のファイルを変更しない。
- 無関係なリファクタリングを同じタスクへ混ぜない。
- 新規依存を勝手に追加しない。追加が必要な場合は理由と代替案を先に報告する。
- 実行していない検証を成功として報告しない。
  失敗や警告がある場合は、コマンド、終了コード、原因、未解決範囲を省略せずに報告する。
- 1 タスクにつき 1 つの確認可能な成果とし、1 PR を原則とする。
  コミットはレビュー可能な意味のある変更単位に分割してよい。
  WIP、fixup、意味のない修正コミットをマージ時に残さない。
  main へのマージは原則 Squash merge とし、main 上では 1 タスク 1 コミットにまとめる。
- スコープ外で発見した問題は、そのタスクで実装せず、残課題として報告する。
- 正の検証と負の検証の両方を実施する。
